## Scope checklist

- `candidate_strategy` on `RetrievalModelConfig` with `nearest` (default, current behaviour), `random`, and `mixed`; no standalone `furthest` (owner-confirmed cut, Q1).
- Deterministic per-batch seeding for random/mixed pools, derived from the batch's example ids; no checkpoint-format growth.
- `t_start`/`t_end` bounds on `VectorStoreDatasetConfig`, applied in the lazy parquet scan, independent of the example datasets' windows.
- Separate corpus filter expression in the experiment file (`cited_by_count >= 1`, no field restriction), store pinned to 1950-2018; a config change, not a CLI flag.
- `--dtype fp32|bf16|fp16` on the train CLI, flowing through `TrainJob` and `build_run_context` into `RunContext.dtype`, with a warning when fp16 is chosen.
- Retriever db buffer and stage-2 pool gather in the compute dtype; stage-1 top-k score matrix and the CLaRa softmax/log-mask loop stay fp32.
- v2.4.1: bfloat16 stores convert to fp32 at the `_gather_store` boundary, covering all five tracker subclasses for both prefixes and the export path.
- v2.4.1: one regression test in a new tests/test_metric_tracker.py (bf16 store round-trips to numpy, export writes fp32 .npy).

Outstanding before merge: the corpus-scope tests (two, mirroring

## Technical approach and risk

Architecture choices settled by the proposals: strategy selection lives
inside `VectorRetriever.search` after the date mask and relaxation ladder;
random pools use Gumbel-perturbed scores through the existing `torch.topk`;
`mixed` builds one pool at one fixed ratio; corpus bounds apply at load
time, `t_end` exclusive; dtypes are explicit end to end, no autocast, and
fp16 ships with a warning rather than an error; eval stays fp32 for now
(checkpoint loads upcast silently); the bf16 fix converts only bfloat16 at
the gather boundary, the single read path every tracker crosses.

Friction points and descope triggers, carried from the proposals:

- MAJOR (candidate-strategy). Recompile churn under `--compile max-autotune`: the Gumbel topk must survive the compile path. Trigger: a probe script on Strix Halo compiles one training step per strategy (plus one bf16 compiled step); if the Gumbel path graph-breaks or recompiles beyond a handful of shapes, fall back to fixed-width padded pools; if padding does not fix it, cut random and mixed and ship the topic as the fixed-width nearest refactor only.
- MAJOR (candidate-strategy). Random and mixed pools lower stage-1 recall. Trigger: if mixed at the fixed ratio lands worse than the nearest baseline at equal epochs on the val window (epoch-1 tracker table), cut random and mixed; the release then reduces to corpus-scope and compute-dtype.
- MAJOR (corpus-scope). Silent corpus subsampling: the widened filter likely saturates `_DB_MAX_ROWS` (250k against 58k today) and samples without a loud signal. Trigger: at first run with the widened filter, read the startup log; if M saturates max_rows, raise the cap knowingly or keep the narrower corpus; if neither, cut the widened-filter wiring and ship t-bounds only.
- MAJOR (corpus-scope). Pool width and VRAM scale back up: eval pools saturate at `n_candidates` (50k) and the bf16 pool gather returns to about 39 GB. Trigger: startup probe of min-eligible at the latest example date; if the projected bf16 pool plus overhead exceeds the 64 GB partition, lower `_N_CANDIDATES` in the same commit (confirmed acceptable before cutting the corpus, Q4); if candidate quality then suffers, cut the widened filter instead.
- MAJOR (compute-dtype). Resuming or evaluating a bf16 run loads weights into an fp32-constructed model, so a resume without the flag silently runs fp32. Trigger: if the resume-boundary metrics shift against the pre-resume trend (metric_tracker table), cut bf16 as the working dtype first; thread `--dtype` through eval only if bf16 is re-enabled afterward (order confirmed, Q3). The plumbing and fp32 path are never cut.
- MAJOR (compute-dtype). fp16 gradient underflow in AdamW with no GradScaler. Trigger: grad-norm probe on the first batches of an fp16 run; if gradients underflow, cut fp16 from the CLI choices, keep bf16.
- v2.4.1 carries no MAJOR or BLOCKING findings. One trigger: if its regression test fails on the owner's torch build (bf16 CPU `torch.cat` or export failure), convert each store element before the concat; the test runs first in the merge series.

MINOR frictions recorded in the proposals (transient fp32 copies, bf16
matmul digits under `mat_mul_precision = "high"`, ladder-1 relaxation being
silent, partial warning coverage, export payload gains a column, resume
dataloader-order caveat on mixed pools) are on record in the proposal files
and need no triggers here.
