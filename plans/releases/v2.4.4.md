# v2.4.4 — Preprocess embed/tokenise step execution restored

Status: implemented 2026-09-09 (owner instruction: commit the fixes now;
patch version only). This doc is the scope contract. After ratification,
features below are locked until a descope trigger fires; the checklist
may shrink but not grow without a new proposal.

Proposal source: owner session, 2026-09-08/09 — an `embed:` preprocess op
produced no embedding column, and a multi-column embed op crashed polars.
Diagnosis and fix in the same session.

Patch number check: two behavior fixes with no user-visible contract
change (the embed op's documented behaviour is restored, not changed),
which is what plans/releases/README.md reserves x.y.z for.

## Scope checklist

- `run_preprocess_pipeline` executes `EmbedStep` and `TokeniseStep`
  handlers again. The step loop's `isinstance` guard only admitted
  `CleanStep`/`DropNaStep`, so embed (and tokenise) ops were parsed,
  recorded in `metadata.json`, and then silently skipped: the embedder
  was instantiated up front and never called, and the output parquet had
  no `*_embedding` column. Non-filter steps now run through the same
  `HANDLERS` dispatch; only the row-delta logging stays filter-only.
- `_run_embed` aliases the bos/eos literal wrapping back to the source
  column (`(...).alias(col)`). The wrapped expression's default output
  name is `literal`, so an embed op naming two columns
  (e.g. `embed:title,abstract`) produced two `literal` expressions in one
  `with_columns` and polars raised
  `ComputeError: the name 'literal' passed to LazyFrame.with_columns is
  duplicate`. Single-column embed ops were unaffected, which is why the
  bug survived the 2.1 refactor.
- Stray `import torch` in `src/data/preprocess/pipeline.py` (added during
  the hotfix session, unreferenced) never committed and dropped from the
  working tree; no commit content.

## Out of scope (parked)

- Preprocess resume / skip-finished-ids: the owner's hotfix (destination
  id anti-join, continuation `part_{i}(n).parquet` filenames) stays
  uncommitted and moves to the 2.5 preprocess-resume work per
  plans/proposals/v2.11-preprocess-resume.md. Known hotfix gaps to close
  there: `scan_parquet([])` on an empty destination, zero-row partition
  guards, `sorted(files)` stable glob order, and `(0)`-vs-`(1)` suffix
  numbering.
- Embedding `title` and `abstract` as separate columns (current behaviour
  is one concatenated `title_abstract_embedding` column) — a behaviour
  change if wanted, so it needs its own proposal.

## Technical approach and risk

Both fixes are inside `run_preprocess_pipeline`/`_run_embed` and touch no
step specs, no CLI surface, and no job serialisation: `PreprocessJob`
round-trips unchanged, and `metadata.json` content is unchanged (the
embedder metadata was already recorded). Friction points:

- MINOR. Runs that relied on the silent skip (i.e. every embed op shipped
  since 2.1) will now actually run model inference during
  `sink_parquet`, so wall-clock time and memory per part jump and a GPU
  is strongly recommended via `--op-embedder-config '{"device":"cuda"}'`.
  Any dataset produced with an `embed:` op before this fix lacks the
  embedding column and must be regenerated; there is no partial state to
  migrate because nothing was written.
- MINOR. Tokenise ops regain their effect too (`*_tokens` columns are
  produced again by `tokenise:` ops that were equally skipped). Same
  regeneration caveat as above for tokenise-only datasets.

Cost: two small diffs in one file plus this doc — smaller than 2.4.2.
