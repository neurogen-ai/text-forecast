# Plan 2.3 — Retrieval-forecast model and vector store

> **Scope:** add a CLaRa-style retrieval-forecast experiment: a vector store
> dataset loading precomputed parquet embedding columns into an in-memory
> (FAISS or matmul) index, a `RetrievalForecast` model with differentiable
> straight-through top-k retrieval over a candidate pool, and the
> `retrieval_forecast` experiment DI config wiring them together.
> Additive only; no existing CLI surface, dataset, or pipeline behaviour
> changes.
>
> **Written retroactively** after implementation (the work landed as three
> commits: vector store dataset, `RetrievalForecast` model, experiment
> config). This file records scope and decisions; it was not used to drive
> the implementation.
>
> **Prerequisites:** plan 2.1 (implemented).
>
> **Out of scope:** GPU FAISS (the stage-1 search stays CPU FAISS /
> torch matmul; revisit if the corpus grows past ~1M vectors), lazy heavy
> imports (plan 2.2), Modal runtime tidy-up (plan 2.5).

## 1. Components

### 1.1 Vector store dataset (`src/data/datasets/retrieval_dataset.py`)

- `VectorStoreDatasetConfig`: parquet source + embedding column, optional
  polars filter predicate (may reference columns beyond the embedding
  column), `max_rows` cap, L2 normalisation toggle, `time_col` +
  `delta_years` recency metadata.
- Loads the embedding column into an `(M, D)` float32 tensor; builds a
  `faiss.IndexFlatIP` when faiss is importable, otherwise falls back to
  torch matmul in `search()`. Search is no-grad stage-1 candidate
  selection only; recency filtering and differentiable re-scoring live in
  the model's `VectorRetriever`, which keeps one exact code path and
  avoids faiss-version-dependent search params.
- An empty post-filter frame is a hard error (an `(0,)`-shaped db
  otherwise surfaces downstream as a confusing `db.size(-1) != embed_dim`
  failure).

### 1.2 Model (`src/models/retrieval_forecast.py`)

- `RetrievalForecast`: query embedder → stage-1 top-k candidate pool →
  CLaRa straight-through top-k (He et al., 2026, Algorithm 1) over the
  pool with the `delta_years` date-eligibility mask → transformer over
  queries × retrieved vectors → binary threshold output.
- Hard dim check at construction: db trailing dim must equal
  `RetrievalModelConfig.embed_dim`.

### 1.3 Experiment (`src/config/experiments/retrieval_forecast.py`)

- DI config wiring both datasets and the model; shared `cited_by_count >= 1`
  filter for training rows and the retrieval corpus; `_DB_MAX_ROWS`,
  `_DELTA_YEARS`, `_TOP_K`, `_N_QUERIES` hyperparameters documented inline.

## 2. Verification

- `tests/test_retrieval_store.py`: FAISS/matmul path equivalence, delta
  recency filtering (stage-1 pool and hard picks), straight-through
  top-k forward exactness and hand-derived gradient check.
