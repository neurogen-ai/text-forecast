# v2.4.3 — Candidate-strategy Gumbel sampling: on-device noise and backend-only temperature

Status: implemented 2026-09-08 (owner instruction: implement now, vet
before any user-facing exposure; patch version only). This doc is the
scope contract. After ratification, features below are locked until a
descope trigger fires; the checklist may shrink but not grow without a
new proposal.

Proposal source: owner session, 2026-09-08 — "the new random candidates
strategy seems really really slow" plus the scope decision to keep the
new smoothing dial backend-only ("just hardcode the tau value in the
backend don't expose it yet we'll test it now and vet before a user
facing change (patch version only)").

Patch number check: perf and a backend-only constant with no config or
contract change, which is what plans/releases/README.md reserves x.y.z
for. The tau knob is deliberately NOT a config field in this release;
exposing it would be a contract change and needs its own (minor)
release.

## Scope checklist

- `VectorRetriever.search` draws the seeded Gumbel noise on the scores'
  device with a same-device generator, instead of a CPU generator plus a
  per-call H2D copy of a full (B*N, M) tensor. This was the dominant
  cost of the random/mixed strategies (it ran on every search call).
  Resume reproducibility is preserved (same seed folded from batch ids,
  same device); pools are not byte-identical to the historical CPU
  stream, so results can differ across device types.
- Backend-only `GUMBEL_TAU` constant in `src/models/retrieval_forecast.py`:
  random-strategy and mixed-minority sampling now use
  `topk((scores / GUMBEL_TAU) + gumbel)`. 1.0 preserves the previous
  cosine-proportional weighting exactly (modulo the RNG device above);
  larger values smooth toward uniform over date-eligible rows, tau -> 0
  sharpens to nearest. Not exposed via config.

## Out of scope (parked, from the same session diagnosis)

- Removing the `k_pool` `.item()` host sync and the `_batch_seed`
  `.item()`: pool purity requires a Python-int pool width for topk, and
  the seed must be a Python int for the generator; removal changes pool
  semantics or adds device-side generator seeding subtleties for little
  gain next to the noise-draw fix. Revisit only if profiling still shows
  search on the step-time critical path.
- Skipping the score matmul for a near-uniform (very large tau) random
  strategy: micro-opt, only worth it once tau semantics are vetted.
- `MIXED_RANDOM_RATIO` 0.25 to 0.75 and `_DB_MAX_ROWS` 350k remain the
  owner's uncommitted working-tree changes, outside this release.

## Technical approach and risk

Both changes are inside `VectorRetriever.search`'s date-filtered exact
path. The temperature divides before the Gumbel add; `-inf` masked slots
stay `-inf` under division and addition, so pool purity (AD1/AD3) is
unchanged for any tau. "nearest" is byte-identical to pre-2.4.3.

Friction points and descope triggers:

- MINOR. tau=1.0 plus the on-device RNG already changes the noise stream
  vs the historical CPU draw, so any A/B against pre-2.4.3 pools must
  account for that. Trigger: if the vetting run needs bit-identical
  baseline pools, pin the comparison to the same device type and accept
  the CPU-stream difference as documented.
- MINOR. tau interacts with score scale (cosine sims in [-1, 1]), so the
  dial is coarse at the extremes. If tuning feels jumpy, normalize
  scores by their per-row std before dividing; not in this release.

Cost: two small diffs in one function plus this doc.
