# Plan 2.1 — Clean pipeline refactor

> **Scope:** replace the integer clean `level` with per-operation step specs,
> make preprocessing steps an ordered list on the job instead of fixed
> call order in `run_preprocess_pipeline`, and rebuild the preprocess CLI
> surface on top of that. Includes a regression test for the suspected
> length-filter sign error in `src/data/preprocess/clean.py`.
>
> **Prerequisites:** none; this is the first post-2.0 release.
>
> **Out of scope:** Modal runtime tidy-up (plan 2.2), describe/engineer
> pipelines, tokenise/embedder internals. Their job fields move into the new
> step model but their behaviour does not change.

---

## 1. Problems being fixed

### 1.1 The intensity knob conflates four operations

`clean.py::main(lf, col, min_len, level)` gates unrelated behaviour behind
`level > 1` through `level > 4` while the docstring documents three levels.
The four behaviours are:

- lowercasing (`level > 1`)
- quality/language substring filtering (always on, no flag)
- statistical length trimming (levels 3–4)
- terminal-period requirement (`level > 4`)

No combination other than the hardcoded prefixes is expressible.

### 1.2 The length filter looks inverted

Level ≥3 computes `low = max(mean - 3σ, min_len)`, `high = mean + 3σ`, then:

```python
lf = lf.with_columns(
    pl.when(pl.col(f"{col}_len") > low)
    .then(pl.lit(None, dtype=...))   # nulls everything LONGER than low
    ...
)
if level > 3:
    ... pl.when(pl.col(f"{col}_len") < high).then(None)  # nulls shorter than high
```

Taken literally this keeps only rows with `low < len < high`, which nulls
nearly everything at level 3. Almost certainly two flipped comparisons.
Task T0 writes the failing test before anything is refactored, so the fix
lands with proof of intent rather than a guess.

Also note `min_len` currently only enters as a floor on a mean-based bound;
the new design makes it a direct hard minimum.

### 1.3 Parallel lists as a job interface

`PreprocessJob` carries three order-coupled lists:

```python
clean_cols: list[str]
clean_levels: list[int]
clean_min_len: list[int]
```

zipped together inside the pipeline, with an all-or-nothing length assertion
in the app layer. Adding any clean parameter means touching the job, the CLI,
and the zip. Same fragility applies to `tokeniser`/`tokenise_cols` and
`embedder_key`/`embed_cols`.

### 1.4 Fixed operation order

`run_preprocess_pipeline` hardcodes the sequence: license/date/field filters,
then clean, then drop-na, then embed, then tokenise, per partition. The user
cannot reorder (e.g. drop-na before clean) or repeat a clean pass without
editing pipeline code.

### 1.5 Filter-list hygiene

`Filter.exclude_quality` contains `"copyright"` twice; `exclude_lang`
duplicates its single-character Chinese particle block verbatim. The class is
a frozen dataclass used as a namespace for what are really module constants.

## 2. Design

### 2.1 Step specs

Frozen dataclasses, one per pipeline operation, in
`src/data/preprocess/steps.py` (new module):

```python
@dataclass(frozen=True, kw_only=True)
class CleanStep:
    col: str
    lowercase: bool = False
    drop_quality: bool = True          # Filter.exclude_quality substrings -> null
    lang_policy: Literal["mark", "drop", "off"] = "mark"
    trim: LengthTrim | None = None
    require_terminal_period: bool = False

@dataclass(frozen=True)
class LengthTrim:
    min_chars: int | None = None       # hard minimum, replaces min_len
    max_sigma: float | None = None     # mean + sigma * max_sigma upper cut
    # exact semantics settled by T0's green test

@dataclass(frozen=True, kw_only=True)
class TokeniseStep:
    tokeniser: str
    cols: tuple[str, ...]

@dataclass(frozen=True, kw_only=True)
class EmbedStep:
    embedder_key: str
    embedder_kwargs: dict[str, Any]
    cols: tuple[str, ...]

@dataclass(frozen=True, kw_only=True)
class DropNaStep:
    cols: tuple[str, ...]
```

All steps tagged by a union type `PipelineStep`. Each gets a handler function
`(lf: pl.LazyFrame, step: XStep, ctx: StepContext) -> pl.LazyFrame` registered
in a dispatch dict keyed by type. `StepContext` carries the runtime, embedder
instance, partition index, and logger so handlers stay pure w.r.t. the frame.

### 2.2 Job changes

`PreprocessJob` replaces the parallel lists and scattered op fields with:

```python
steps: tuple[PipelineStep, ...]
```

Removed fields: `clean_cols`, `clean_levels`, `clean_min_len`,
`tokeniser`, `tokenise_cols`, `embedder_key`, `embedder_kwargs`,
`embed_cols`, `drop_na_cols`. Kept unchanged: origin, destination,
partitioning, date/field/language/type filters, license handling, dry-run,
max_threads, runtime_name, params. Steps must be JSON-serialisable for Modal
dispatch (they already are: plain dataclasses of primitives); add
`to_dict`/`from_dict` via `dataclasses.asdict` plus a tag field per step.

Execution loop becomes:

```python
for step in job.steps:
    lf = HANDLERS[type(step)](lf, step, ctx)
```

Row-count delta logging moves into the dispatcher so every step reports
"dropped N rows" uniformly (replaces the clean-only `_measure_lf` pair).

### 2.3 CLI

Decision point between two surfaces, to be settled when implementation starts:

- **Option A (recommended): repeatable ordered `--op` flags.**

  ```
  text-forecast preprocess <origin> \
      --op "clean:title" --lowercase --trim-min-chars 20 \
      --op "dropna:title,abstract" \
      --op "embed:title+abstract" --embedder modernbert
  ```

  Flag position defines execution order. Op-specific params apply to the most
  recent op. Typer parses repeated options in order; params accumulate onto
  the current op builder. Less elegant help text, far less plumbing.

- **Option B: subcommand chain** (`preprocess clean ... then embed ...`).
  Most expressive, but Typer has no native sequencing story; it needs a
  custom multi-command parser or a positional DSL. Not worth it until Option A
  hurts.

Either way the old flat flags (`--clean-col` etc.) are removed, not
deprecated: the only consumer is the user's own invocations, and 2.x has no
back-compat promise across minors.

### 2.4 Filter lists

`Filter` dissolves into plain deduplicated module constants in `clean.py`
(`EXCLUDE_QUALITY`, `EXCLUDE_LANG`). Dedupe pass included in T1.

## 3. Implementation tasks

Each task fits one session and lands as one commit.

- **T0 — Regression test for length trimming.**
  Construct a small LazyFrame with known length distribution; assert the
  intended behaviour (drop rows outside `[min, mean ± 3σ]`). Confirm it fails
  against current `clean.py`; capture which comparison signs are wrong in the
  commit message. This pins intent before the refactor.
- **T1 — `steps.py` specs + refactored `clean.py`.**
  New step dataclasses and union; dissolve `Filter` into deduped constants;
  rewrite `clean.main` as the `CleanStep` handler operating from explicit
  flags instead of `level`. Unit tests per flag combination (T0's test ports
  here).
- **T2 — Job and pipeline rewiring.**
  Replace job fields with `steps: tuple[PipelineStep, ...]`; dispatcher loop
  with uniform row-delta logging; serialisation round-trip test (job → dict →
  job) since Modal dispatch depends on it. Local runtime path fully green.
- **T3 — CLI rebuild.**
  `apps/preprocess.py`: ordered-op parsing (or subcommand chain if Option B
  won), validation moved from `assert` to explicit raises (asserts vanish
  under `python -O`), updated help text. End-to-end smoke test on a small
  local parquet fixture.
- **T4 — Docs.**
  Update `docs/data-pipeline.md` (step model, trimming semantics), 
  `docs/apps.md` (new CLI surface with examples), and the plans index status.
  README quickstart if it shows preprocess flags.

## 4. Risks

- **Trimming semantics ambiguity.** If T0 reveals the current behaviour was
  intentional, stop and re-specify `LengthTrim` before proceeding. Do not
  silently preserve inverted comparisons.
- **Modal dispatch contract.** Jobs cross the Modal boundary as pickled
  dataclasses today. The steps tuple must survive that path; T2's round-trip
  test covers it, but a manual `--runtime modal` dry run belongs in T4's
  checklist.
- **Silent behaviour drift for existing workflows.** Old level-based
  invocations have no automatic translation. Document a mapping table
  (old level → equivalent flags) in `docs/data-pipeline.md` so past runs are
  reproducible.
