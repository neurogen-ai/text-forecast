# Proposal: independent corpus scope for the vector store

Release: v2.4.0-expanded-query-search-strat. The number was freed by
renumbering the drafted Modal tidy-up chain to 2.5-2.8 (owner decision,
recorded in plans/releases/README.md).

Status: implemented on branch 2.4 (corpus scope commit; about 30 lines across
src/data/datasets/retrieval_dataset.py and
src/config/experiments/retrieval_forecast.py).

Correction on record (2026-09, implementation closeout): the inherited
uncommitted code deviated from this proposal in two places — the store window
started at 1920-01-01 (not the pinned 1950-01-01) and the "widened" corpus
filter still carried an 11-field restriction. Both were corrected to spec in
the corpus-scope closeout commit. The startup log now also carries the
pre-sampling corpus row count and the effective window (the MINOR mitigation
below); the example date range is not in that line because the store class
has no access to example windows. Bounds and widened-filter tests added to
tests/test_retrieval_store.py.

## Context

Before this change the corpus and the example datasets shared one filter
expression, and the store loaded every publication year. The example datasets
already had `t_start`/`t_end` windows (docs/experiments.md documents the
convention); the store had none, so post-window rows entered the pool.
One framing correction before this goes further: a corpus `t_end` bounds
absolute recency only. The `delta_years` cutoff is relative to the example
date, and ladder 2 (fewer than `top_k` eligible rows) drops the filter
entirely by setting the cutoff to +inf, so a t-bounded corpus can still hand
a ladder-relaxed old example rows much newer than itself; the bound narrows
the blast radius, it does not close it. Use case from the owner: train on
Chemistry examples while retrieving from a corpus of all fields.

There is no research note; plans/research/ is empty. Evidence: the 2.3
release doc's component list (store config owns its own filter), and the
existing time-window convention in src/data/datasets/polars_dataset.py.

## Features

- `t_start`/`t_end` bounds on `VectorStoreDatasetConfig`, applied to the time
  column during the lazy parquet scan, independent of the example datasets'
  windows.
- The experiment wires a separate corpus filter expression
  (`cited_by_count >= 1` without the field restriction) so example scope and
  corpus scope can differ, with the store pinned to `1950-01-01 <= date <
  2018-01-01`.

## Architecture decisions

- AD1. Bounds and filter apply at load time in the lazy polars frame.
  Rejected alternative: filtering after collect, or masking at search time.
  Post-collect filtering wastes the load, and search-time masking cannot
  shrink the db tensor, which is the point when the corpus is the wider side.
- AD2. `t_end` exclusive, `t_start` inclusive. Rejected alternative:
  inclusive `t_end`. It would break the one-window convention
  polars_dataset.py and docs/experiments.md already establish, and put an
  off-by-one at every window boundary.
- AD3. The recency ladder and `delta_years` carry over unchanged against
  whatever corpus loads. Rejected alternative: interaction rules between
  corpus bounds and the ladder. Widening or narrowing the corpus does not
  need new semantics; the existing ladder already relaxes when a narrow
  corpus starves an example. Note the warning coverage is partial: ladder 2
  (filter dropped) warns once, ladder 1 (delta relaxed to 0) is silent
  (src/models/retrieval_forecast.py).
- AD4. The wider-corpus use case stays a config change in the experiment
  file (two filter expressions), not a new CLI surface. Rejected
  alternative: a `--corpus-field` style CLI flag. Experiment files own the
  object graph by contract (docs/experiments.md); per-field CLI flags would
  duplicate that ownership.

## Risk assessment

Friction points:

- MAJOR. Silent corpus subsampling. Dropping the Chemistry restriction will
  likely push the store past `_DB_MAX_ROWS` (250k against 58k today), and
  `VectorStoreDataset` then samples without a loud signal; the run's corpus
  becomes an arbitrary field mix. Contact points:
  src/data/datasets/retrieval_dataset.py max_rows branch; the startup log
  line "vector db (M, D)". Descope trigger: at first run with the widened
  filter, read the startup log; if M saturates max_rows, either raise the cap
  knowingly or keep the narrower corpus; if neither, cut the widened-filter
  wiring and ship the topic as t-bounds only.
- MAJOR. Pool width and VRAM scale back up with corpus breadth: wider corpus
  raises the batch-minimum eligible count, eval pools saturate at
  `n_candidates` (50k), and the bf16 pool gather returns to about 39 GB.
  Contact points: VectorRetriever.search k_pool computation; the 64 GB GPU
  partition on the Strix Halo venue (docs/strix-halo-container.md). Descope
  trigger: startup probe of min-eligible at the latest example date; if the
  projected bf16 pool plus fixed overhead exceeds the partition, lower
  `_N_CANDIDATES` in the same commit; if candidate quality suffers, cut the
  widened filter instead.
- MINOR. Embedding provenance: rows entering a widened corpus must carry
  embeddings from the same preprocess run. Same source name enforces this
  today; record it, no trigger needed.
- MINOR. The relaxation ladder can silently weaken the delta guarantee when
  a narrow t-bounded corpus starves examples: ladder 2 warns once, ladder 1
  (delta to 0) does not warn at all. A corpus-bound change makes silent
  ladder-1 relaxation more likely, so the corpus row count and the example
  date range belong in the same startup log line; no trigger beyond that.

Cost to build:

- Small, and mostly spent: the code exists uncommitted. Remaining work is two
  tests mirroring test_retrieval_store.py's store-construction pattern
  (bounds applied, widened filter independent of example filter) and the
  commit itself.

Descope triggers, named cuts:

- max_rows saturation without an acceptable cap or sample: cut the widened
  filter wiring; keep t-bounds.
- VRAM budget exceeded and `_N_CANDIDATES` reduction unacceptable: cut the
  widened filter wiring; keep t-bounds.
