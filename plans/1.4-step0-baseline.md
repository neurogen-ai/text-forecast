## Step 7 — sub-plan 1.4.5 (tracker arity awareness)

- **1.4.5**: trackers derive output arity from the tensors they receive
  instead of assuming one column. `MetricTracker` gains
  `_infer_n_out(logits)` (last dimension of the gathered logits store; flat
  stores count as single-output). `BinaryClassificationTracker.calc_metrics`
  branches on it: `n_out == 1` keeps the existing binary code path
  verbatim, `n_out > 1` routes to a new `_calc_multilabel_metrics` with
  per-class threshold metrics (0.5) aggregated macro and micro
  (`{prefix}_F1:macro`, `_precision:micro`, ...) and per-class PR/ROC plots
  capped at the first 10 classes (log line when capping). Store-name prefix
  scheme unchanged, no new tracker subclasses.

  batch captured pre-change (`/tmp/binary_synth_baseline.json`, capture
  script `/tmp/capture_binary_baseline.py`) and compared post-change in
  `tests/test_tracker_arity.py::test_binary_path_byte_identical` — exact
  float equality on all logged metrics.
