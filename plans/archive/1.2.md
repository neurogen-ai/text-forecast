# Plan 1.2 — Modal runtime for preprocessing

> **Scope:** implement the first Modal backend on top of the `Runtime`,
> `DataSource`, and `TextEmbedder` abstractions introduced in plan 1.1.
> The entire `preprocess` job must be able to run inside a Modal container,
> reading raw data from a Modal volume and writing staged output back to a
> Modal volume, with embedding performed by a batched Modal GPU class.
> Local execution remains the default and must be unchanged for developers
> without Modal credentials.
>
> This plan is the second step of a larger runtime unfold; see plans 1.3 and
> 2.0 for the remaining apps.

---

## 1. Goal

`citef preprocess` can run in two modes:

- **local** (default): reads/writes local paths via `LocalStagedSource` and
  embeds text with the local HuggingFace model.
- **modal**: reads/writes Modal volumes, runs the whole preprocessing job
  inside a Modal function/container, and uses a batched Modal GPU class for
  embedding.

A single `--runtime modal` flag switches modes. App logic in
`src/apps/preprocess.py` does not branch on the runtime string; it only calls
`build_runtime(...)` and delegates to the runtime.

---

## 2. Principles

| # | Principle |
|---|---|
| P1 | **One app, two runtimes.** `preprocess.py` contains no `if runtime == "modal"` blocks. |
| P2 | **Source abstraction.** `DataSource` is the only path-like object the app sees. |
| P3 | **Embedder abstraction.** `TextEmbedder` is the only embedding interface the app sees. |
| P4 | **Whole-job remote execution.** The runtime can dispatch the entire preprocessing pipeline to Modal, not just individual embedder calls. |
| P5 | **Lazy, explicit resources.** Modal volumes, images, and GPU containers are loaded only when `modal` is selected. |
| P6 | **Local-first regression safety.** Local smoke tests must pass without Modal credentials and without code changes. |

## 4. Runtime protocol refinements

Add an explicit preprocessing dispatch method so the app does not need to know
whether it is running locally or remotely:

```python
class Runtime(Protocol):
    def get_source(self, root: str | Path, name: str) -> DataSource: ...
    def get_embedder(self, key: str, **kwargs: Any) -> TextEmbedder: ...
    def maybe_download(self, source: DataSource) -> Path: ...
    def maybe_upload(self, source: DataSource, local_path: Path) -> None: ...
    def run_preprocess(self, job: PreprocessJob) -> DataSource: ...
```

- `run_preprocess` is the only entry point `preprocess.py` calls after parsing
  CLI args and building sources.
- `LocalRuntime.run_preprocess` executes `run_preprocess_pipeline(...)` in-process.
- `ModalRuntime.run_preprocess` serialises the job, invokes a Modal function
  mounted with the relevant volumes, and that function executes
  `run_preprocess_pipeline(...)` inside the container.

## 5. Data sources

### 5.1 `src/data/sources/modal.py`

```python
@dataclass(frozen=True, kw_only=True)
class ModalVolumeSource:
    volume_label: str
    path: str
    name: str

    def resolve(self) -> Path:
        return Path("/modal") / self.volume_label / self.path / self.name
```

- `resolve()` returns the in-container path so Polars can read/write parquet
  transparently.
- The runtime is responsible for ensuring the volume is mounted at that path
  when a Modal function runs.

### 5.2 Volume layout

Use two volumes mirroring `[env].raw_loc` and `[env].staged_loc`:

- `raw_volume` — contains raw OpenAlex parquet datasets.
- `staged_volume` — contains cleaned/tokenised/embedded outputs.

This keeps the local and Modal layouts identical and avoids one dataset per
volume sprawl.

## 6. Embedder backend

### 6.1 `src/data/preprocess/embed_modal.py`

Implement a `ModalEmbedder` that conforms to `TextEmbedder`:

```python
class ModalEmbedder:
    def __init__(self, model_name: str, batch_size: int, output_dim: int, app_ref: modal.App | modal.Cls, ...):
        ...

    @property
    def output_dim(self) -> int: ...

    def encode(self, texts: list[str]) -> list[list[float]]:
        # Call Modal GPU function via .remote()
        ...
```

- `output_dim` is provided at construction time (read from a small config or
  fetched once from a lightweight Modal metadata call) so Polars can build the
  correct `pl.Array` dtype client-side.
- The client wrapper is what `preprocess.py` sees; it is still a `TextEmbedder`.

### 6.2 Modal GPU class

In `src/runtime/modal.py` (or a new `src/runtime/modal_embed.py`):

```python
@modal.cls(
    gpu="T4",  # or configurable, e.g. "A10G", "H100"
    image=preprocess_image,
    volumes={"/modal/<staged-volume>": staged_volume},
)
class ModalEmbeddingGPU:
    @modal.enter(snap=True)
    def setup(self):
        # Load tokenizer and model once per container
        ...

    @modal.batched(max_batch_size=64, wait_ms=200)
    def encode(self, texts: list[str]) -> list[list[float]]:
        # Reuse mean-pooling logic from embed_huggingface.py
        ...
```

- `@modal.enter(snap=True)` enables memory snapshots for fast cold starts.
  GPU memory snapshots require the same flags already used in
  `production/service.py`: `enable_memory_snapshot=True` on the class decorator
  plus `experimental_options={"enable_gpu_snapshot": True}`.
- `torch.compile` must stay **off** inside snapshotted containers (compilation
  can break snapshot restore). The embedder's compile default is already off
  (plan 1.1 §6.3); do not enable it for Modal embedders.
- `@modal.batched` amortises GPU invocation overhead across many small batches.
- The GPU class lives inside the Modal runtime module because it is a runtime
  implementation detail, not a generic embedder.

## 7. Preprocessing pipeline refactor

### 7.1 `src/data/preprocess/pipeline.py`

Move the core preprocessing logic out of `src/apps/preprocess.py` into a
runtime-agnostic function:

```python
@dataclass(frozen=True, kw_only=True)
class PreprocessJob:
    origin: DataSource
    destination: DataSource
    clean_cols: list[str]
    clean_levels: list[int]
    clean_min_len: list[int]
    tokeniser: str
    tokenise_cols: list[str]
    embedder_key: str
    embedder_kwargs: dict[str, Any]
    embed_cols: list[str]
    n_partitions: int
    rows_per_part: int
    compression_level: int
    start_date: datetime | None
    end_date: datetime | None
    field_id: list[int]
    drop_na_cols: list[str]
    languages: list[str]
    types: list[str]
    filt_license: bool
    replace_non_permissive_cols: list[str]
    dry_run: bool
    max_threads: int


def run_preprocess_pipeline(job: PreprocessJob, runtime: Runtime) -> DataSource:
    ...
```

- This function contains all the filtering, cleaning, tokenising, partitioning,
  and embedding logic currently in `src/apps/preprocess.py`.
- It receives a `Runtime` so it can resolve additional sources or upload/download
  if needed; for a local run this is `LocalRuntime`.
- It is called in-process by `LocalRuntime.run_preprocess` and inside the Modal
  container by `ModalRuntime.run_preprocess`.

### 7.2 Embedding inside the pipeline

```python
embedder = runtime.get_embedder(job.embedder_key, **job.embedder_kwargs)
...
.with_columns(
    pl.col("to_embed")
    .map_batches(
        lambda s: embedder.encode(s.to_list()),
        return_dtype=pl.Array(pl.Float32, width=embedder.output_dim),
    )
    .alias(f"{' '.join(job.embed_cols)}_embedding")
)
```

- The pipeline is agnostic to whether `embedder.encode` runs locally or calls
  Modal remotely.

## 9. Modal runtime implementation

### 9.1 `src/runtime/modal.py`

Responsibilities:

- Hold references to Modal `App`, `Image`, and `Volume` objects.
- Implement `get_source(...)` returning `ModalVolumeSource`.
- Implement `get_embedder(...)` returning `ModalEmbedder` configured to call the
  local Modal GPU class.
- Implement `run_preprocess(job)`:
  1. Validate that referenced volumes exist or `create_if_missing=True` is set.
  2. Construct a Modal function decorated with the correct volume mounts.
  3. Pass the serialisable `PreprocessJob` to the function.
  4. Inside the function, build a lightweight `LocalRuntime` (in-container paths
     are already local) and call `run_preprocess_pipeline(job, local_runtime)`.
  5. Return the destination `DataSource` to the caller.

### 9.2 Modal image

```python
preprocess_image = (
    modal.Image.debian_slim(python_version="3.13")
    .pip_install_from_pyproject("pyproject.toml")
    .add_local_dir("src", remote_path="/root/src")
    .env({"PYTHONPATH": "/root/src"})
)
```

- The project uses a **flat src-layout**: `apps`, `config`, `data`, `models`,
  `training`, `utils`, `builders` are top-level packages under `src/`. The
  image must put `src/` on `PYTHONPATH` — `add_local_python_source("src")`
  does **not** do this.
- `pip_install_from_pyproject` installs *dependencies only* (polars, torch,
  transformers, scikit-learn, typer, ...), keeping the image in sync with
  `pyproject.toml`. The project itself is never pip-installed into the image;
  `src/` on the path covers it and stays in sync with local code on every
  deploy.
- `config/config.toml` is deliberately **not** baked into the image: everything
  the container needs arrives via the serialised job (sources, embedder key and
  kwargs), and from plan 2.0 onwards an `Env` carried by the job.
- Use the same Python version as the local environment (3.13).

### 9.3 Volume mounts

```python
@app.function(
    volumes={
        "/modal/<raw-volume>": modal.Volume.from_name(raw_volume),
        "/modal/<staged-volume>": modal.Volume.from_name(staged_volume),
    },
    image=preprocess_image,
)
def run_preprocess_remote(job: PreprocessJob) -> DataSource:
    ...
```

- Keep volume labels configurable via `config.toml [runtime.modal]` or CLI flags.

### 9.4 Packaging: Modal is an optional dependency

`modal` is currently **not** in `pyproject.toml` at all. Local installs must
not require it (P5/P6):

1. `pyproject.toml` gains:
   ```toml
   [project.optional-dependencies]
   modal = ["modal"]
   ```
2. `src/runtime/factory.py` imports `runtime.modal` lazily inside the
   `"modal"` branch only; on `ImportError` raise a clear error:
   `"The modal runtime requires the 'modal' extra: pip install citation-forecast[modal]"`.
3. No module outside the Modal runtime modules (`src/runtime/modal.py`,
   `src/data/preprocess/embed_modal.py`, `src/data/sources/modal.py`) may
   import `modal` at module import time.

## 10. Config changes

`config/config.toml` is gitignored (it contains machine-specific paths), so the
repository provides a tracked `config/config.example.toml` with the new
`[runtime]` section. Copy or merge it into your local `config/config.toml`:

```toml
[runtime]
default = "local"

[runtime.modal]
project = "my-modal-project"
raw_volume = "openalex-raw"
staged_volume = "openalex-staged"
gpu = "T4"
embedder_batch_size = 64
```

- `load_env()` may load this section and pass it to `build_runtime()`.
- Keep `[env]` focused on machine-independent paths and MLflow URI; put
  backend-specific knobs under `[runtime]`.
- `[runtime].default` is honoured by **every** app (`preprocess` here;
  `describe`/`engineer` in 1.3; `train`/`eval` in 2.0). The `--runtime` CLI
  flag overrides it per invocation. This keeps the `notes.md` promise:
  switching execution venue is a single flag (or one config key), never a code
  change.

## 11. Verification

```bash
# Local smoke test (unchanged from 1.1)
citef preprocess <origin> -n <name> --runtime local --embedder modernbert-base --embedder-device cpu

# Modal smoke test (requires Modal credentials and volumes)
citef preprocess <dataset-name> -n <name> --runtime modal --embedder modernbert-base
```

Expected:

- Local run passes without Modal credentials **and without the `modal` package
  installed**; `--runtime modal` on such a machine fails with the clear
  "install the modal extra" message from §9.4.
- Modal run reads from the configured raw volume and writes to the staged volume.
- Embedding inside Modal uses the GPU class and produces the same output schema
  as the local embedder.
- `metadata.json` records `runtime: modal` and the embedder key/config.
- No `AttributeError` or direct `import config` references.

## 12. Go / no-go: does this stay in v1.2?

**Stay in v1.2.** This release adds one new runtime backend for one app. The
public CLI contract is additive (`--runtime modal` plus optional Modal config),
and local users are unaffected. The work is the natural completion of the
abstractions introduced in 1.1.

Promote to v2.0 only if the scope expands to:

- Production deployment infrastructure beyond a single ad-hoc Modal function
  (scheduled jobs, web endpoints, CI/CD for Modal images, secrets management).
- Moving `train` or `eval` onto Modal GPUs.
- Dataset versioning, incremental updates, or long-running Modal jobs with
  monitoring/retry logic.

These larger items are intentionally deferred to plans 1.3 and 2.0.

## 12. Local Modal runtime testing

### 12.1 Goal

Developers must be able to exercise the Modal runtime path on their own machine
without deploying to Modal's cloud. This is achieved by running the Modal app as
a **local service** with local directories mounted as Modal volumes.

### 12.2 Setup

1. Install the optional Modal dependency:
   ```bash
   pip install -e ".[modal]"
   ```

2. Merge the `[runtime]` block from `config/config.example.toml` into your
   local `config/config.toml`:
   ```toml
   [runtime]
   default = "local"

   [runtime.modal]
   project = "citef-local"
   raw_volume = "openalex-raw-local"
   staged_volume = "openalex-staged-local"
   gpu = "T4"
   embedder_batch_size = 64
   ```

3. Ensure the configured raw volume contains a small test dataset. When running
   locally, Modal mounts the volume label to `/modal/<volume_label>`; the
   runtime's `ModalVolumeSource.resolve()` returns the in-container path, so a
   dataset named `works` is expected at `/modal/openalex-raw-local/works`.

### 12.3 Running a local Modal service

Start the Modal app in local development mode. This keeps the runtime alive and
lets the CLI invoke `run_preprocess_remote` through the local Modal server:

```bash
modal serve src/runtime/modal.py
```

In another shell, run the preprocess app against the local service:

```bash
citef preprocess works -n works-preprocessed --runtime modal --embedder modernbert-base
```

Because the Modal runtime is selected, `ModalRuntime.run_preprocess` serialises
the job and dispatches it to the locally-served Modal function. The function
runs inside the local Modal container, reads from the mounted raw volume, and
writes to the mounted staged volume.

### 12.4 One-shot local execution

For a single local invocation without keeping a service alive, use Modal's
local run mode:

```bash
modal run --local src/runtime.modal::run_preprocess_remote
```

This path is primarily for debugging the remote function itself; the CLI smoke
test in §12.3 is the preferred local integration test.

### 12.5 Expected local-Modal behaviour

- The job completes without requiring real Modal cloud credentials.
- The output directory `/modal/openalex-staged-local/works-preprocessed` (or the
  configured staged volume mount) contains the same parquet files and
  `metadata.json` as a local run.
- `metadata.json` records `runtime: modal` and the same embedder key/config.
- Embedding is performed by `ModalEmbeddingGPU` running in the local Modal
  container (CPU-only if no GPU is available on the workstation).
