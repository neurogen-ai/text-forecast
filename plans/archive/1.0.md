## 1. Current state (read this first)

The project is a Typer CLI (`citef`, entry `src/main.py`) with sub-apps in
`src/apps/` (`train`, `eval`, `preprocess`, `describe`, `engineer`).

Configuration today is a "code-as-config" **singleton package** `src/config/`:

- `src/config/env.py` — paths + MLflow `TRACKING_URI` and **`EXPERIMENT`** name.
- `src/config/model.py` — picks a model class (`models.EmbedGraphClass`) and builds
  its pydantic config at module level.
- `src/config/data.py` — builds train/test dataset configs (pydantic) +
  `DataLoaderConfig`s inside `@dataclass` wrappers (`Train`, `Test`).
- `src/config/train.py` — picks `trainer` / `evaluator` **classes** directly, plus
  hyperparameters (`lr`, `epochs`, `loss_fn` as a registry **string**, etc.).
- `src/config/__init__.py` — imports all submodules eagerly and asserts
  `env.STAGED_LOC.exists()` **at import time**.

Wiring today is done manually inside `src/apps/train.py` and `src/apps/eval.py`:

- The apps `import config` at module top, then construct: model, datasets,
  `DataLoader` (`src/data/dataloaders/DataLoader.py::DLWrapper`), loss
  (`builders/build_loss.py`, string registry), optimizer
  (`builders/build_optimizer.py`, string registry), LR scheduler, progress bars.
- **Tracker:** `src/builders/build_tracker.py` hardcodes
  `_tracker = tracking.BinaryClassificationTracker` at module level and builds long
  `StoreParams` tuples for train/eval. This is the "tracker builder" that must be
  integrated into DI.
- **Checkpoints:** save/load logic is inlined in the apps
  (`torch.save` + `mlflow.log_artifact` in train; `client.download_artifacts` in
  both). There is no abstraction — this is where Checkpoint processors go.
- `Trainer`/`Evaluator` (`src/training/trainers/base_trainer.py`,
  `src/eval/base_evaluator.py`) are ABCs with pydantic configs; the app loop calls
  `trainer.step(batch)` / `evaluator.step(batch)`.

Existing typing idioms to **match** (do not invent a new style):

- PEP 695 generics: `class Model[T_Config, T_In, T_Out](Protocol)`
  (`src/models/protocols.py`), `class GraphDataset[T_Config](Dataset[...])`,
  `class DLWrapper[T_Output]`.
- Classes expose their config schema as a class attribute `config` and are
  constructed as `Clss(config=..., env=...)`.
- pyright runs in **strict** mode (`pyrightconfig.json`), pythonVersion currently
  says 3.12 but the code requires 3.13 (`pyproject.toml`) and already uses PEP 695.

Registries (`src/utils/registry.py`) exist for losses, optimizers, models, datasets.
They are in tension with direct-in-config instantiation; their fate is covered in
Phase 5 and Question block G.

**Known sharp edges the refactor must fix:**

1. `import config` executes everything at import time → experiment cannot be
   selected at runtime; CLI parsing happens after config is frozen.
2. Tracker class is hardcoded in a builder, not selectable per experiment.
3. Checkpoint I/O is copy-pasted app code, no local/aws/other pluggability.
4. MLflow experiment name lives in `env.py`, not with the rest of the experiment.
5. Trainer/Evaluator ABCs are half-DI (class picked in config, assembled in app).

## 2. Goal

A single **experiment module** (plain Python file) per experiment, e.g.
`src/config/experiments/graph_embed_class.py`, that:

1. Declares `experiment_name: str` (used for `mlflow.set_experiment(...)`).
2. **Directly instantiates** (no string registries) the full object graph:
   - Data Sources *(new class type)*
   - Data Formaters *(new class type)*
   - DataSets
   - Samplers
   - DataLoaders
   - Model
   - Training/Eval **Strategy** *(replaces Trainer/Evaluator)*
   - Metric Tracker *(absorbs `build_tracker.py`)*
   - Checkpoint processor *(new class type; local / MLflow-artifact / future S3)*
3. Is selected at runtime, with precedence:
   **top-level CLI arg `--experiment/-e`** → **`config/config.toml`** (repo root,
   key `experiment`) → hard error listing available experiments.
4. Is fully checkable by pyright (strict) **while editing the config file**:
   missing args, wrong types, and positional-args-where-keywords-are-expected must
   be flagged in Zed/nvim. Achieve this with `Protocol`s, PEP 695 generics,
   `kw_only=True` dataclasses / pydantic models, and keyword-only (`*`) signatures.
5. Is shaped so a future PyTorch Lightning adoption is a thin adapter, not a
   rewrite: strategy hooks named `training_step` / `validation_step` /
   `configure_optimizers`; checkpoint format a dict; strategy classes hold no
   direct `mlflow` calls (tracker owns logging).

**Non-goals** (do not touch): `production/` (Modal service), `preprocess` /
`describe` / `engineer` apps' internal logic, actual training math, dataset IPC
caching internals, model architectures.


## 4. Core contracts (write these FIRST — everything else implements them)

Create `src/config/protocols.py` (or split into the domain packages and re-export —
pick one, be consistent). Match the PEP 695 style of `src/models/protocols.py`.
**Every constructor introduced below must be keyword-only** (`def __init__(self, *, ...)`)
or a pydantic `BaseModel` / `@dataclass(kw_only=True)` so pyright flags unnamed args.

```python
# --- sketch; refine names to taste, keep semantics ---

class Configurable[T_Config](Protocol):
    config: type[T_Config]

class DataSource(Protocol):
    """Where raw data lives. Resolves to something scannable."""
    def scan(self) -> pl.LazyFrame: ...        # or .path -> Path; see Q-C2
    @property
    def name(self) -> str: ...

class Formater[T_In, T_Out](Protocol):          # NOTE: project spells it "Formater"
    def __call__(self, row: T_In) -> T_Out: ...

class CheckpointProcessor(Protocol):
    def save(self, *, state: Checkpoint, epoch: int, run: RunInfo) -> str: ...   # returns URI/path
    def load(self, *, ref: CheckpointRef, map_location: torch.device) -> Checkpoint: ...

class TrainStrategy[T_Batch](Protocol):
    def start_epoch(self, epoch: int) -> None: ...
    def training_step(self, batch: T_Batch) -> float: ...
    def configure_optimizers(self) -> tuple[Optimizer, LRScheduler]: ...   # shape TBD, Q-F4

class EvalStrategy[T_Batch](Protocol):
    def validation_step(self, batch: T_Batch) -> float: ...
```

The assembled graph — `@dataclass(kw_only=True)` in `src/config/experiment.py`:

```python
@dataclass(kw_only=True)
class Experiment:
    experiment_name: str            # mlflow.set_experiment(experiment_name)
    model: nn.Module                # generic later if needed; nn.Module is enough today
    train_loader: DLWrapper
    val_loader: DLWrapper
    strategy: TrainStrategy | EvalStrategy   # or two fields; see Q-F1
    tracker: MetricTracker
    checkpoints: CheckpointProcessor
    epochs: int
    eval_interval: int
    checkpoint_interval: int
    # train_examples_per_epoch / val_examples_per_epoch if still needed by progress bars
```

And the runtime — `@dataclass(frozen=True, kw_only=True)` in `src/config/runtime.py`:
`device`, `dtype`, `subsample: int | None`, `compile_mode: str`, `fullgraph: bool`,
`mat_mul_precision: str`. (Extend as the apps require; keep it small.)

**IDE-checking trick (mandatory):** every experiment module must end with a typed
entry point so pyright checks the *whole file's* assembly against `Experiment`:

```python
# src/config/experiments/graph_embed_class.py
experiment_name: str = "General-2-graph-embed"

def build(runtime: RunContext) -> Experiment:
    ...            # instantiate everything here, keyword args only
    return Experiment(experiment_name=experiment_name, ...)
```

The loader validates at runtime too: after import, assert the module has
`build` (or a module-level `EXPERIMENT: Experiment` if Q-B1 decides module-level),
call it, and `isinstance`-check the result against the dataclass.

## 5. Implementation phases

### Phase 0 — Selection plumbing (no behavior change yet)

1. Create `config/config.toml` at repo root:
   ```toml
   experiment = "graph_embed_class"
   ```
2. Create `src/config/loader.py`:
   - `available_experiments() -> list[str]` — scan `src/config/experiments/*.py`.
   - `resolve_experiment_name(cli_value: str | None) -> str` — CLI →
     `tomllib` load of `<repo root>/config/config.toml` → `ValueError` with the
     available list. Use `src/utils/get_root_dir.py` to locate the root.
   - `load_experiment(name: str, runtime: RunContext) -> Experiment` —
     `importlib.import_module(f"config.experiments.{name}")`, call `build(runtime)`,
     type-check result, return it. Clear error if module/function missing.
3. Create `src/config/runtime.py` (`RunContext`) and `src/config/experiment.py`
   (`Experiment`) per §4 — fields may start as `Any`-light but protocols land in
   Phase 1; do not leave `Any` in the final state.
4. `src/main.py`: add a root `@app.callback()` taking
   `experiment: str | None = typer.Option(None, "--experiment", "-e")`, resolve the
   name via `resolve_experiment_name`, store on `ctx.obj` (a small dataclass or
   dict). Sub-commands already accept `ctx: typer.Context` (eval does; add to
   train) and read `ctx.find_root().obj`.
   **Acceptance:** `citef --experiment nope train` fails fast with the available
   list; `citef train ...` (toml present) still runs the old code path untouched.

### Phase 1 — Protocols + new class types (additive only)

5. Write all protocols from §4 in their final homes. Re-export from
   `src/config/protocols.py` if split.
