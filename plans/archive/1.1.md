# Plan 1.1 — Migrate remaining apps to v1.0 config shape + robust preprocessing

> **Scope:** complete the migration of the remaining old-code apps so that the
> Phase-0 PEP 562 shim in `src/config/env.py` can be removed. *Additionally*,
> make `preprocess` robust enough to support pluggable embedding models and
> introduce the runtime/data-source abstractions that plan 1.2 will use for the
> local/Modal split. This plan is authored in Phase 7 of plan 1.0 (v3) and
> implemented afterwards.

---

## 1. Goal

All apps read machine settings through `config.env.load_env(...)` and never
`import config` for singleton values. Once this is true, the temporary
`__getattr__` shim in `src/config/env.py` can be deleted.

On top of that migration, `preprocess` must stop being a single-purpose
ModernBERT script and become a runtime-agnostic preprocessing driver:

- Embedding is no longer hard-coded; models are selected by name/config and
  loaded lazily.
- The app can run identically on local workstations and (later) inside Modal
  containers by changing only the runtime backend, not the app logic.
- Path resolution goes through `DataSource`-style objects so that local paths
  and Modal volumes can be swapped with minimal wiring.

Non-goals: adding new ML functionality, changing dataset IPC caching, real S3,
model architectures, or the actual Modal deployment (that is plan 1.2 /
possibly 2.0). The experiment-file *format* stays as-is, with exactly one
exception: the minimal `build(runtime, env)` signature change in §8, which is
required both to delete the shim safely and to make experiment files portable
for plan 2.0.

## 2. Current state

After plan 1.0 (v3) phases 0–7:

- `src/apps/train.py` and `src/apps/eval.py` are fully rewired: they build
  `Env` from CLI overrides, construct `RunContext`, and load an `Experiment`.
- `src/apps/preprocess.py`, `src/apps/describe.py`, and
  `src/apps/engineer.py` still rely on the Phase-0 shim:
  - `describe.py` imports `from config import env` and reads `env.STAGED_LOC`.
  - `engineer.py` had a dead `import config` removed in Phase 7 but is
    otherwise untouched.
  - `preprocess.py` does not currently touch project config, but it hard-codes
    paths/defaults and should be brought onto the same `load_env` path for
    consistency.
- Two further shim consumers are **not** data-pipeline apps and were overlooked
  in earlier revisions of this plan:
  - `src/config/experiments/graph_embed_class.py` and `transformer_class.py`
    do `from config.env import ARTIFACT_LOC, STAGED_LOC, TRACKING_URI`,
    baking machine-absolute paths into the experiment modules at import time.
    Besides blocking shim removal, this breaks plan 2.0's core requirement
    that the *same experiment file* run unchanged inside a Modal container
    (see `plans/notes.md`: "the code running remains identical").
  - `src/apps/chat.py` (currently unregistered in `src/main.py`) reads
    `env.TRACKING_URI` and `env.EXPERIMENT`.
  - `src/data/datasets/-gdbak.py` is a leftover backup file. Legacy datasets
    such as `polars_dataset.py` declare their own `Env` protocol and take an
    `env` constructor param — they do not import the shim themselves, but
    verify no caller passes the `config` module into them.
- `src/config/env.py` still exposes legacy module-level names via PEP 562
  `__getattr__`. This was intentionally kept only until these apps migrate.
- `src/apps/preprocess.py` embeds text with a globally-loaded,
  hard-coded `answerdotai/ModernBERT-base` model at module import time. The
  model, tokenizer, device, and mean-pooling logic are baked into `embed_batch`,
  making the feature impossible to test without CUDA, impossible to reuse with
  another embedding model, and impossible to run under Modal without rewriting
  the app.

## 3. Locked decisions

| # | Decision |
|---|---|
| K1 | Apps use `config.env.load_env(cli_overrides)`; no `import config` anywhere. |
| K2 | `describe`/`engineer`/`preprocess` get the same four `[env]` CLI override flags as train/eval (`--tracking-uri`, `--raw-loc`, `--staged-loc`, `--artifact-loc`) for consistency, even if some are unused. |
| K3 | Path defaults come from `config/config.toml [env]`; CLI overrides replace them. |
| K4 | Once all three apps are migrated, delete the `__getattr__` shim in `src/config/env.py` entirely. |
| K5 | No shared base class or config module for these apps; each app owns its own argument parsing and env consumption. |
| K6 | Embedding models are loaded **lazily** and selected by a string key or experiment-style config; no global model/tokenizer state in `preprocess.py`. |
| K7 | Embedding logic is split into a small provider/protocol so that local HuggingFace inference and future Modal/serverless inference share the same call shape. |
| K8 | Runtime/backend selection is introduced as an abstraction in 1.1 but only implemented for `local`. The abstraction must be rich enough to support `modal` in 1.2 without changing app code. |
| K9 | `DataSource` remains the path-resolution boundary; `preprocess`/`describe`/`engineer` resolve inputs/outputs through sources rather than raw `Path` arithmetic against `env.raw_loc`/`env.staged_loc`. |
| K10 | Keep changes minimal and do not implement the actual Modal deployment in this plan. |
| K11 | Experiment modules receive machine settings explicitly: the contract becomes `build(runtime: RunContext, env: Env)` and experiment files never import from `config.env`. The experiment still decides *what* dataset/model/processor to use (B1); only the *where* arrives via `Env`. This is what makes the same file runnable inside a Modal container in plan 2.0. |
| K12 | `chat.py` (unregistered in `main.py`) is migrated to `load_env()` + `resolve_experiment_name(...)`, or deleted. Shim removal requires one of the two. |
| K13 | `src/data/datasets/-gdbak.py` is deleted. Legacy datasets with their own `Env` protocol param (e.g. `polars_dataset.py`) are left alone unless they import the shim. |

## 5. Per-app migration

### 5.1 `describe`

- Add `ctx: typer.Context` parameter if not already present.
- Add the four `[env]` CLI override flags.
- Build `env = load_env(overrides={...})` at the top of `main`.
- Replace `env.STAGED_LOC` usage with a `LocalStagedSource(path=env.staged_loc,
  name=dataset).resolve()`.
- The dataset filter currently hard-coded in Phase 7 should become an optional
  CLI flag (e.g. `--min-cited-by-count`, `--min-referenced-works`) or accept a
  raw Polars expression string, so `describe` no longer needs to know the train
  dataset schema. The minimal Phase-7 inline expression is a stop-gap only.
- Log env-derived paths for user visibility.

### 5.2 `engineer`

- Add `ctx: typer.Context` and the four `[env]` CLI override flags.
- Build `env = load_env(...)`.
- Resolve input via `LocalStagedSource(path=env.staged_loc, name=input_dataset)`
  when a dataset name is given; use the explicit `input_path` otherwise.
- Export engineered output under a new `LocalStagedSource(path=env.staged_loc,
  name=output_name)` unless an explicit output path is given.
- Remove any remaining accidental references to `config` module attributes.

### 5.3 `preprocess`

- Add the four `[env]` CLI override flags.
- Build `env = load_env(...)`.
- Change `origin` from a required `Path` argument to a `str` argument that is
  resolved by the runtime: if it is an existing filesystem path, use it directly;
  otherwise treat it as a dataset name and resolve it through
  `runtime.get_source(root=env.raw_loc, name=origin)`.
- Default destination to `runtime.get_source(root=env.staged_loc, name=<name>)`
  when `name` is provided; otherwise derive a name from `origin`.
- Keep filtering, cleaning, tokenising, and partition logic unchanged unless
  required by the embedder refactor below.
- Re-register the preprocess subcommand in `src/main.py` (it is currently
  commented out).

## 6. Preprocessing robustness & embedding generalisation

### 6.1 Remove module-level model loading

- Delete the global `tokenizer`/`model`/`device` construction in
  `src/apps/preprocess.py`.
- Do not call `torch.cuda.empty_cache()` or `model.compile()` unconditionally.
- Move all embedding concerns into `src/data/preprocess/embed.py` and an
  implementation module.

### 6.2 Embedder protocol

Introduce a small protocol, e.g.:

```python
class TextEmbedder(Protocol):
    @property
    def output_dim(self) -> int: ...
    def encode(self, texts: list[str]) -> list[list[float]]: ...
```

- `encode` accepts plain Python lists and returns plain Python lists so it can
  be called from Polars `map_batches` or from a Modal function without leaking
  framework tensors across boundaries.
- Register implementations under a short key (e.g. `"modernbert-base"`) via the
  existing `@component` marker / `utils.build_helper` mechanism.

### 6.3 HuggingFace local implementation

Create `src/data/preprocess/embed_huggingface.py`:

- Accept `model_name: str`, optional `device: str | None`, `batch_size: int`,
  `dtype: str`, and `pooling: str` (start with `"mean"`).
- Load tokenizer and model lazily inside `__post_init__` or first `encode` call,
  not at import time.
- Validate `device`: prefer user override, then CUDA if available, then CPU.
- Support mean pooling with attention masking. Guard padding-only samples and
  empty strings.
- Return `Float32` vectors of width `output_dim`.
- Keep `torch.compile` optional and off by default, controlled by config/CLI,
  because compile can break in some environments (e.g. Modal memory snapshots).

### 6.4 CLI / config wiring

- Replace the current `--embed-model` free-text string with a `--embedder` key
  that maps to a registered embedder.
- Add `--embedder-config` / `--embedder-batch-size` / `--embedder-device` flags
  (or accept a JSON/TOML snippet) so the same app can drive different models
  without code changes.
- If no embedder is selected, skip embedding entirely (current behaviour when
  `--embed-model` is empty).
- Persist the chosen embedder key and config in `metadata.json`.

### 6.5 Polars integration

- Keep `pl.col(...).map_batches(...)` but call `embedder.encode(...)` inside the
  helper rather than closing over globals.
- Derive the output `pl.Array(pl.Float32, width=embedder.output_dim)` from the
  embedder instance.

## 7. Runtime abstraction (local/Modal prep)

Introduce `src/runtime/` with a minimal boundary so that 1.2 can add a Modal
backend without touching app logic.

### 7.1 `Runtime` / `RuntimeProvider`

```python
class Runtime(Protocol):
    """Execution backend: resolves paths, volumes, embedders, and remote jobs."""
    def get_source(self, root: str | Path, name: str) -> DataSource: ...
    def get_embedder(self, key: str, **kwargs: Any) -> TextEmbedder: ...
    def maybe_download(self, source: DataSource) -> Path: ...
    def maybe_upload(self, source: DataSource, local_path: Path) -> None: ...
```

- `LocalRuntime` is the only implementation in 1.1. It returns
  `LocalStagedSource`, the local HuggingFace embedder, and no-ops for
  upload/download.
- The protocol deliberately includes `get_embedder` and `maybe_upload` now so
  that 1.2 only has to supply a `ModalRuntime` implementation; apps should not
  need to change the way they request an embedder or publish results.
- In 1.2, `ModalRuntime` will implement the same protocol using Modal volumes
  and cached downloads.

### 7.2 App integration

- Add a `--runtime` CLI flag defaulting to `"local"`. Only `"local"` is valid
  in 1.1; validation should reject `"modal"` with a clear "coming in v1.2"
  message.
- Apps build a runtime instance from the flag and `env`, then resolve all
  sources and embedders through it.
- `preprocess.py` should request its embedder via `runtime.get_embedder(...)`
  rather than constructing it directly from the registry; this keeps the app
  unchanged when `ModalRuntime` supplies a remote embedder in 1.2.
- The same `--runtime modal` flag and `Runtime` protocol will be the only
  switch needed in 1.2.

## 8. Experiment env injection (prerequisite for shim removal)

The experiment modules currently pull machine paths from the shim
(`from config.env import ARTIFACT_LOC, STAGED_LOC, TRACKING_URI`). Besides
blocking shim removal, this hard-codes one machine's absolute paths into files
that plan 2.0 must execute unchanged inside a Modal container. The fix is to
inject the typed `Env` into the experiment entry point; the experiment still
decides *what* dataset/model/processor to use (plan 1.0 B1) — only the *where*
arrives via `Env`.

1. `src/config/loader.py`:
   - `load_experiment(name, runtime, env)` and
     `load_experiment_from_path(path, runtime, env)` gain a required keyword
     argument `env: Env`, forwarded to the module's `build(runtime, env)`.
   - Update the contract-validation error messages to state that experiment
     modules must define `build(runtime: RunContext, env: Env)`.
2. `src/config/experiments/graph_embed_class.py` and `transformer_class.py`:
   - Delete `from config.env import ARTIFACT_LOC, STAGED_LOC, TRACKING_URI`.
   - Change the entry point to `def build(runtime: RunContext, env: Env)`.
   - Replace `STAGED_LOC` → `env.staged_loc`, `ARTIFACT_LOC` →
     `env.artifact_loc`, `TRACKING_URI` → `env.tracking_uri`.
3. Call sites: `src/apps/train.py` passes its already-loaded `env` into
   `load_experiment(...)`; `src/apps/eval.py` passes it into
   `load_experiment_from_path(...)`. No CLI changes.
4. `src/apps/chat.py`: either migrate its `env.TRACKING_URI` /
   `env.EXPERIMENT` reads to `load_env()` +
   `config.loader.resolve_experiment_name(...)`, or delete the file (it is not
   registered in `src/main.py`). Choose one — the shim cannot be removed while
   it reads legacy names.
5. Delete `src/data/datasets/-gdbak.py`. Grep the legacy datasets
   (`polars_dataset.py` and its subclasses) for shim imports; they define
   their own `Env` protocol and take `env` as a constructor param, so they
   should need no changes — confirm no caller passes the `config` module.

**Acceptance:** no file under `src/` imports `TRACKING_URI`, `RAW_LOC`,
`STAGED_LOC`, `ARTIFACT_LOC`, or `EXPERIMENT` from `config` / `config.env`;
`citef --experiment graph_embed_class train -s smoke --no-gpu --subsample 512`
still completes an epoch with the env-injected build.

## 9. Shim removal

After the above apps are verified:

1. Delete `_default_env()` and `__getattr__()` from `src/config/env.py`.
2. Remove the `typing.Any` import if it becomes unused.
3. Verify with ripgrep that no legacy module-level names remain:
   - `rg "from config import env"` → no matches.
   - `rg "from config\.env import .*(TRACKING_URI|RAW_LOC|STAGED_LOC|ARTIFACT_LOC|EXPERIMENT)"` → no matches.
   - `rg "\benv\.(TRACKING_URI|RAW_LOC|STAGED_LOC|ARTIFACT_LOC|EXPERIMENT)\b"` → no matches.
     (Lowercase reads such as `env.staged_loc` are the legitimate `Env`
     dataclass and must keep working.)

  `build(runtime, env)` (§8), so no `config.env` import exists anywhere.

## 11. Future steps (input for plan 1.2)

- **F-13. DataSource adoption in preprocess/describe/engineer.** Once
  `LocalStagedSource` (and any future sources) cover these apps' path needs,
  consider whether `[env].raw_loc` and `[env].staged_loc` should be retired
  entirely, leaving only `tracking_uri` and `artifact_loc` in `[env]`.
- **F-14. Unified logging of env params.** Log the loaded `Env` values as MLflow
  params in any app that starts a run.
- **F-15. Modal preprocess runtime (plan 1.2).** Implement `ModalRuntime`,
  `ModalVolumeSource`, and a batched GPU `ModalEmbedder` so that the entire
  preprocessing job can run inside a Modal container reading from and writing
  to Modal volumes.
- **F-16. Modal data-pipeline apps (plan 1.3).** Apply the same runtime
  abstraction to `describe.py` and `engineer.py` so the full data pipeline can
  run on Modal volumes.
- **F-17. Config-driven runtime defaults.** Allow `config.toml` to declare a
  default runtime and per-backend settings (e.g. volume names) so local and
  Modal runs differ only by a config section, not by CLI flags.
- **F-18. Modal train/eval runtime (plan 2.0).** Extend the runtime abstraction
  to `train.py` and `eval.py`, enabling full experiments to run on Modal GPUs.
  This is the natural boundary for a major-version bump.
- **F-19. Production deployment hardening (plan 2.1).** Add CI/CD for Modal
  images, scheduled jobs, web endpoints, secrets management, and monitoring.
