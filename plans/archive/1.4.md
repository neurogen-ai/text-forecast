# Plan 1.4 — Training abstraction amendments

> **Scope:** implement the six abstraction amendments identified in
> `docs/change-overview.md` §6. These are internal refactors of the batch,
> model-protocol, loss, dataset, tracker, and weight contracts. No new
> features, no behaviour changes beyond improved numerics and louder failure
> modes. Engine, Experiment, Strategy protocol, checkpointing, and the
> experiment-file pattern are all untouched.
>
> This plan slots between the Modal data-pipeline work (plans 1.2–1.3) and
> the Modal train/eval work (plan 2.0). The refactors should land first so
> the v2.0 runtime migration builds on clean contracts rather than migrating
> the current drift.

---

## 1. Goal

After this plan:

- One canonical batch definition shared by datasets, models, strategies,
  losses, and trackers.
- Every model follows a single protocol form (`config` class attribute +
  `forward(batch) -> Output`), enforced by a conformance test.
- Losses consume logits only; models never compute sigmoid inside
  `forward`.
- Truncation vs row-dropping is an explicit enum with logged counts.
- Trackers derive output arity from the tensors they receive instead of
  assuming one column.
- Batch weights use `Optional`, not NaN sentinels.

## 2. Versioning rationale

**This is v1.4, not 1.2.x patches.** Plans 1.2 and 1.3 are drafted but
unreleased; patch numbers off them (`1.2.1+`) would interleave with
unreleased Modal work and make release history ambiguous. The six items are
also too cross-cutting to ride along inside the runtime unfold. They stay
below the v2.0 boundary because nothing here changes how experiments are
declared, run, or resumed — only the internal shapes of the objects those
experiments compose.

Sub-plans are numbered `1.4.1`–`1.4.6` and may be released individually as
patch releases on the 1.4 line once 1.4.0 lands the shared pieces.

## 3. Sub-plan 1.4.1 — Canonical batch types

### Problem

"What a model may expect from a batch" exists only as scattered Protocols:
`BatchInput` in model files, `BCEBatch` in losses, `_Batch` in strategies.
None reference each other, and the mask shape contract differs per file
(`TextTokenDataset` emits an expanded square `(T, T)` mask).

### Changes

- Create canonical batch NamedTuples in `src/data/datasets/types.py`
  (extending what is already there):
  - `TokenBatch`: `id, x (B,T) long, y, mask (B,T) bool, weight | None`.
  - Graph/scalar variants as needed by existing datasets.
- Datasets emit these types directly. `TextTokenDataset.__getitem__` stops
  expanding the mask to `(T, T)` and returns plain `(B, T)`.
- Update consumers of the square mask:
  - `TransformerClass` / `TransformerLM`: pass
    `attn_mask=mask[:, None, None, :]` to SDPA (broadcast key-padding).
  - Strategies' `_Batch` protocols import from `data.datasets.types`.
  - Loss protocols (`BCEBatch`) likewise.
- Add conformance test: every `@component` class under `src/models/` must
  accept a synthetic batch of the declared input type and return a value
  exposing `.logits`. This turns forward-signature drift into loud failures.

### Verification

```bash
pytest tests/test_batch_conformance.py
citef --experiment transformer_class train -s smoke --no-gpu --subsample 512
```

## 4. Sub-plan 1.4.2 — Standardise the Model protocol

### Problem

`models/protocols.py::Model` declares a `config` class attribute, but legacy
models use `config_schema = ModelConfig` and/or `filepath`
(e.g. `TransformerLM`, `h_attn`). Forward signatures also split between
`forward(batch)` and `forward(x, mask)`. basedpyright strict cannot flag
this because most old models never declare conformance to the protocol.

### Changes

- Redefine `Model[T_Config, T_Batch, T_Out]` as the single protocol:
  `config: type[T_Config]` plus `forward(self, batch: T_Batch) -> T_Out`.
- Migrate every model under `src/models/` mechanically:
  - `config_schema` → `config`.
  - `forward(x, mask)` → `forward(batch)` taking the canonical batch type
    from 1.4.1.
  - Drop `filepath` where present.
- All models declare conformance to the protocol so the type checker sees
  violations.
- Legacy models that are no longer worth migrating get an explicit
  `# legacy:` header comment and are excluded from the conformance test
  list, so exclusion is visible rather than accidental.

### Verification

```bash
basedpyright src/models/
pytest tests/test_batch_conformance.py
```

## 5. Sub-plan 1.4.3 — Logits-only loss contract

### Problem

Losses consume `.probs`; models therefore compute sigmoid inside `forward`,
which is numerically worse than logit-space loss and forces every head to
expose a probability field regardless of its output semantics.

### Changes

- `BinaryCrossEntropyLoss` switches to
  `binary_cross_entropy_with_logits(output.logits, ...)`.
- `LossFn` protocol documents logits-only input.
- Models stop computing probs in `forward`; `Output.probs` becomes optional
  or is computed lazily where metrics need it (tracker side, detached, in
  logit→sigmoid one call).
- Wasserstein loss family updated the same way if it reads `.probs`.
- `ClassificationStrategy` unchanged apart from no longer expecting `.probs`
  to always be present.

### Verification

Compare loss values old-vs-new on a fixed seed smoke run (should match BCE
to within float tolerance at moderate logits; diverges only at extreme
logits, which is the point).

## 6. Sub-plan 1.4.4 — Explicit truncation policy

### Problem

`truncate_method: str` accepts any string; `"drop"` silently filters out rows
longer than `max_len`, losing data without a trace.

### Changes

- `TextTokenDatasetConfig.truncate_method: Literal["truncate", "drop"]`
  (default `"truncate"`).
- Log affected row counts either way:
  - `"drop"`: number of rows removed by the length filter.
  - `"truncate"`: number of rows that were longer than `max_len` and got cut.
- Same treatment for other dataset configs sharing the option
  (`binary_threshold_dataset` etc.) via a small shared helper if trivially
  extractable, otherwise duplicated two-liner.

## 7. Sub-plan 1.4.5 — Tracker arity awareness

### Problem

Trackers assume a single logit/prob column (`squeeze(-1)` style). A model
with `n_out > 1` crashes or produces nonsense silently.

### Changes

- `MetricTracker.calc_metrics` inspects the first logged logits tensor's
  last dimension and branches binary vs multi-label there.
- Multi-label path: per-class threshold metrics aggregated macro/micro,
  plus the existing PR/ROC plots per class behind a cap (e.g. first 10
  classes) to protect MLflow artifact volume.
- Store-name prefix scheme stays exactly as is; only squeeze/aggregation
  logic gains arity awareness. No new tracker subclasses for arity.
- Existing binary metrics must produce byte-identical results for
  `n_out == 1` runs (regression-test against current outputs).

---

## 8. Sub-plan 1.4.6 — Optional weights instead of NaN sentinels

### Problem

Unused batch weights are signalled by NaN and detected per batch via
`torch.any(torch.isnan(...))`. Fragile: a legitimate NaN propagates as
"unused", and the scan costs per batch.

### Changes

- Canonical batch type (from 1.4.1) carries `weight: Tensor | None`.
- Dataset emits `None` when no weights configured.
- Losses branch on `is None`.
- Remove NaN-sentinel code paths from `TextTokenDataset`,
  `ClassificationStrategy`, and loss modules.

## 9. Implementation order and dependencies

```text
1.4.1 batch types ──► 1.4.2 model protocol ──► 1.4.3 loss contract
        │
        └─────────────► 1.4.6 optional weights

1.4.4 truncation   (independent, can go anytime)
1.4.5 tracker      (independent until n_out>1 models arrive)
```

Each sub-plan is one commit, releasable alone. 1.4.1 unblocks everything
else; do it first even if the rest slip.
