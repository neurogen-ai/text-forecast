## 1. Current state (read this first)

Typer CLI (`citef`, entry `src/main.py`) with sub-apps in `src/apps/`
(`train`, `eval`, `preprocess`, `describe`, `engineer`).

Configuration today is a "code-as-config" **singleton package** `src/config/`:

- `env.py` — module-level constants: `TRACKING_URI`, `EXPERIMENT`, `RAW_LOC`,
  `STAGED_LOC`, `ARTIFACT_LOC`.
- `model.py` — model class + pydantic config built at module level.
- `data.py` — train/test dataset configs + `DataLoaderConfig`s in `@dataclass`
  wrappers (`Train`, `Test`).
- `train.py` — `trainer`/`evaluator` classes + hyperparameters.
- `cuda.py` — `mat_mul_precision` only.
- `__init__.py` — eager imports + import-time `STAGED_LOC.exists()` assert.

Wiring is manual inside `src/apps/train.py` / `src/apps/eval.py`:

- Both `import config` at module top; construct model, datasets, `DLWrapper`
  (`src/data/dataloaders/DataLoader.py`), loss/optimizer via string registries
  (`builders/build_loss.py`, `build_optimizer.py`), LR scheduler via
  `builders/build_lr_scheduler.py` (LinearLR warmup →
  CosineAnnealingWarmRestarts → SequentialLR, params from `config.train`).
- `builders/build_tracker.py` hardcodes
  `_tracker = tracking.BinaryClassificationTracker` + long `StoreParams` tuples.
- Checkpoint save/load is inlined: train does `torch.save` to
  `ARTIFACT_LOC/EXPERIMENT/run_id/epoch-N.pt` + `mlflow.log_artifact`, and
  `client.download_artifacts` on resume; eval does the same download.
- `Trainer`/`Evaluator` ABCs hold engine logic; the app owns the epoch/batch
  loop, scheduler stepping, checkpoint scheduling, and progress bars.
  `BaseTrainer.step` calls `mlflow.log_metric("train_loss-batch", ...)` directly.
- `MetricTracker` takes a `StoreParams` tuple + a loose `config` object;
  maintains GPU-side ring buffers flushed to CPU when full.
- Eval loops time windows via `copy.deepcopy(config.data.test.dataset)` +
  mutating `t_start`/`t_end`, and contains a **dead** `or True` short-circuit
  around downloading `config.py` from run artifacts.

Typing idioms to match: PEP 695 (`class Model[T_Config, T_In, T_Out](Protocol)`,
`GraphDataset[T_Config]`); basedpyright **strict**.

## 3. Goal

A single **experiment module** per experiment at
`src/config/experiments/<name>.py` that:

1. Declares `experiment_name: str` (→ `mlflow.set_experiment(...)`).
2. **Directly instantiates** (no string registries) the full object graph inside a
   typed `build(runtime: RunContext) -> Experiment` entry point: Data Sources,
   Data Formaters, DataSets, Samplers, plain torch DataLoaders, Model, Strategy
   (incl. optimizer/scheduler **specs** + `mat_mul_precision`), Metric Tracker,
   Checkpoint processor.
3. Selection precedence: root CLI `--experiment/-e` → `config/config.toml` key
   `experiment` → hard crash listing available experiments.
4. Fully checkable by basedpyright (strict) **while editing the file** —
   `Protocol`s, PEP 695 generics, `@dataclass(kw_only=True)`, pydantic models,
   keyword-only (`*`) signatures.
5. Lightning-compatible shape (`training_step` / `validation_step` /
   `configure_optimizers`, dict checkpoints, no direct mlflow calls in strategy),
   with an **`Engine`** owning the loop so a later cloud push is an Engine
   implementation swap, not a rewrite.

**Non-goals:** `production/`, `preprocess`/`describe`/`engineer` internals
(→ `plans/1.1.md`), training math, dataset IPC caching internals, model
architectures, real S3, any Lightning dependency, everything in §9.

## 5. Core contracts (write these FIRST)

Home protocols near their domain package; re-export from `src/config/protocols.py`.
PEP 695 style. **All constructors keyword-only.** NamedTuples remain the batch/
boundary types (H3).

```python
# --- DataSource (C1/C2 + J5: source owns its full path; no env root needed) ---
class DataSource(Protocol):
    @property
    def name(self) -> str: ...
    def resolve(self) -> Path: ...        # absolute path the Dataset reads/caches from

@dataclass(frozen=True, kw_only=True)
class LocalStagedSource:                  # src/data/sources/local.py
    path: Path                            # full path, set in the experiment file (J5)
    name: str                             # dataset name, used for cache organisation
    def resolve(self) -> Path: return self.path / self.name

# --- Formater (C3/C4: per-row value transforms only) ---
class Formater[T_In, T_Out](Protocol):
    def __call__(self, row: T_In) -> T_Out: ...

# --- Checkpointing (E2/E3/I3; J1 existence check; J3 default full restore) ---
class Checkpoint(NamedTuple):
    model: dict[str, Tensor]
    optimizer: dict[str, Any] | None      # None when processor slimmed
    scheduler: dict[str, Any] | None
    epoch: int

class CheckpointRef(NamedTuple):
    run_id: str
    epoch: int

class CheckpointProcessor(Protocol):
    def save(self, *, state: Checkpoint, run_id: str) -> str: ...
    def load(self, *, ref: CheckpointRef, map_location: torch.device) -> Checkpoint: ...

# MlflowCheckpointProcessor(artifact_loc: Path, include_optimizer: bool = True,
#                           include_scheduler: bool = True)
# also owns experiment-file artifacts (B4/E5/J1):
#   save_experiment_file(path: Path) -> None
#   experiment_file_exists(run_id: str) -> bool     # client.list_artifacts check
#   download_experiment_file(run_id: str, dest: Path) -> Path

# --- Optimizer / scheduler specs (F4/J2: IDE-checked, core experiment elements) ---
class OptimizerSpec(Protocol):
    def build(self, *, params: Iterable[Tensor]) -> Optimizer: ...

@dataclass(kw_only=True)
class AdamWSpec:
    lr: float
    weight_decay: float
    def build(self, *, params) -> torch.optim.AdamW: ...

class LRSchedulerSpec(Protocol):
    def build(self, *, optimizer: Optimizer) -> LRScheduler: ...

@dataclass(kw_only=True)
class WarmupCosineSpec:                    # reproduces build_lr_scheduler.py exactly
    milestones: tuple[int, ...]
    warmup_start_factor: float
    eta_min: float
    epochs: int
    def build(self, *, optimizer) -> LRScheduler: ...

# --- Strategy (F1/F3/F4 + J10 mat_mul_precision + J3 restore hooks) ---
class Strategy[T_Batch](Protocol):
    def configure_optimizers(self) -> tuple[Optimizer, LRScheduler]: ...
    def start_epoch(self, epoch: int) -> None: ...
    def move_to_device(self, batch: T_Batch) -> T_Batch: ...
    def training_step(self, batch: T_Batch) -> float: ...
    def validation_step(self, batch: T_Batch) -> float: ...
    def scheduler_step(self) -> None: ...            # engine calls once per epoch
    def load_optimizer_state(self, *, optimizer, scheduler) -> None: ...  # J3 resume
    # pydantic config includes: mat_mul_precision: str = "high"  (J10)
    #   applied via torch.set_float32_matmul_precision in __init__/setup

# --- Tracker (F5/J4: dedicated classes, dict stores, CPU-copy per batch,
#      explicit kwargs only — no loose config object) ---
class MetricTracker:
    store_names: ClassVar[tuple[str, ...]] # each subclass declares its own
    def __init__(self, *, device: torch.device, dtype: torch.dtype,
                 export: bool = False, export_loc: Path | None = None) -> None: ...
    # internally: self.stores: dict[str, list[Tensor]]
    # process_values(): NaN-check, value.detach().cpu(), append
    # log_batch_metric(name, value, *, step): owns the mlflow call (F3)

# --- Experiment (H3 + J7: plain torch DataLoaders) ---
@dataclass(kw_only=True)
class Experiment[T_Batch]:
    experiment_name: str
    model: nn.Module
    strategy: Strategy[T_Batch]
    tracker: MetricTracker
    train_loader: DataLoader[T_Batch]      # torch.utils.data.DataLoader, sampler injected
    val_loader: DataLoader[T_Batch]
    checkpoints: CheckpointProcessor
    epochs: int
    eval_interval: int
    checkpoint_interval: int
```

`RunContext` (`@dataclass(frozen=True, kw_only=True)`): `device`, `dtype`,
`compile_mode: str`, `fullgraph: bool`, `subsample: int | None`. Runtime = *how
it runs*; never experiment-relevant values (B1).

`Env` (`@dataclass(frozen=True, kw_only=True)`): `tracking_uri: str`,
`raw_loc: Path`, `staged_loc: Path`, `artifact_loc: Path`;
`load_env(overrides)` reads toml `[env]`, applies CLI overrides (all four keys —
J5), validates `staged_loc.exists()` at **load time**. New code paths take paths
from DataSources, not from `Env` (J5 direction).

### 5.1 Engine contract (J9)

```python
# src/training/engine.py
class Engine[T_Batch]:
    def __init__(self, *, experiment: Experiment[T_Batch],
                 runtime: RunContext, progress: ProgressBars) -> None: ...

    def train_epoch(self, epoch: int) -> None:
        """strategy.start_epoch; loop experiment.train_loader ->
        strategy.training_step; advance progress (totals derived from
        len(loader.sampler) or len(loader.dataset) — J7)."""

    def eval_epoch(self, epoch: int, *,
                   loader: DataLoader[T_Batch] | None = None) -> None:
        """loop loader (default experiment.val_loader) -> strategy.validation_step;
        tracker.calc_metrics(prefix='val', ...). Used by train AND eval apps."""

    def fit(self, *, start_epoch: int, run_id: str) -> None:
        """for epoch in range(start_epoch, start_epoch + exp.epochs):
            train_epoch -> strategy.scheduler_step()
          -> checkpoints.save at checkpoint_interval (full Checkpoint dict — E2)
          -> eval_epoch at eval_interval -> tracker report/clear -> progress."""
```

The **app** retains: CLI parsing, mlflow run lifecycle (`start_run`, param/
artifact logging), resume orchestration (download + `load_state_dict` +
`strategy.load_optimizer_state`), progress-bar construction. The **Engine**
retains zero mlflow-run knowledge; it only calls tracker/processor/strategy.

## 9. Future steps — input for plan 1.0.1 (NOT this plan's scope)

These questions/items surfaced while locking v3. They should be considered —
and answered — when authoring **plans/1.0.1.md**:

- **F-1. DataSource streaming (deferred from C2).** When non-local sources
  arrive (S3/HTTP/Arrow-flight), `resolve() -> Path` no longer fits. Does the
  protocol grow `scan() -> pl.LazyFrame` / `open() -> IO[bytes]`, and do
  datasets then need a streaming mode that bypasses the IPC cache?
- **F-2. `[env]` end state (from J5).** Once 1.1 migrates `preprocess` and
  DataSources own all dataset paths, should `raw_loc`/`staged_loc` be deleted
  from `[env]` entirely, leaving only `tracking_uri` + `artifact_loc`? What do
  `describe`/`preprocess` use instead — per-run DataSource args?
- **F-3. Engine ↔ mlflow boundary (from J9).** Should the Engine own the mlflow
  run lifecycle (`start_run`, param/artifact logging) instead of the app, so
  cloud (Modal) execution becomes "ship Engine + Experiment"? What then
  differentiates an app from an entrypoint?
- **F-4. Hyperparameter search (README v1.0 roadmap).** A sweep runner composing
  experiment files with override grids + MLflow parent/child runs. Open: where
  do grids live (toml? a sweep .py?), and how does that square with B2's
  "one file per experiment, no shared base" reproducibility rule?
- **F-5. Engine ↔ Lightning spike (from F6/I2).** When Lightning is adopted:
  Engine → `lightning.Trainer`, strategy → `LightningModule` wrapper,
  `CheckpointProcessor` → `CheckpointIO`. Timebox a spike to validate the v3
  shapes actually map 1:1 before committing.
- **F-6. S3CheckpointProcessor (from E4).** Real boto implementation, plus the
  credentials/endpoint story (env vars vs `[env]` keys vs instance-profile
  only).
- **F-7. Sampler semantics under plain DataLoaders (from J7).**
  `AutoBinnedSampler`/`PortionSampler` per-epoch reseeding (`set_epoch`
  hooks?), determinism for resume, and progress totals when a sampler's length
  differs per epoch.
- **F-8. Spec coverage (from F4/J2).** Which optimizers/schedulers beyond
  AdamW/WarmupCosine need typed spec wrappers (SGD? OneCycle? plateau?), and
  what's the policy — one wrapper per torch type vs. a generic
  `Spec[T](cls, **kwargs)` escape hatch (which weakens IDE checking)?
- **F-9. Tracker CPU-copy cost (from F5).** Per-batch `.cpu()` sync copies may
  bottleneck large-logit models on GPU runs. Measure; if hot, consider a
  bounded pinned-memory staging buffer behind a tracker kwarg — without
  resurrecting the old StoreParams machinery.
- **F-10. Batch-level Formater / collate_fn (deferred from C3).** A
  batch-level formater plugged into DataLoader `collate_fn`, and whether the
  v1.1 text-embedding roadmap (embed string columns in preprocessing) changes
  what formaters should own.
- **F-11. `production/` alignment.** The Modal service still expects the old
  config/artifact layout; after 1.0 ships, production model packaging (arch +
  weights + experiment file) should adopt the new checkpoint dict and
  experiment-file artifact.
- **F-12. Test suite seed.** `tests/` around loader resolution, checkpoint
  round-trip, and Engine smoke (the §7 optionals) — formalise in 1.0.1 rather
  than growing them ad hoc?
