# Plan 2.5 implementation — distributed GPU training

Implements `plans/releases/2.5.md` against the code as of plan 2.3 (train
pipeline in `src/training/pipeline/train.py`, Engine loop in
`src/training/engine.py`, runtimes in `src/runtime/local.py` and
`src/runtime/modal_runtime.py`). One branch per PR; each step fits one
context window and lands as one commit.

## Context

Today training is strictly single-process. `TrainJob` carries no GPU count;
`RunContext` knows only device/dtype/compile/subsample; the Engine loops over
the experiment's own `train_loader`; `MetricTracker` accumulates CPU stores
per process and logs straight to MLflow; `MlflowCheckpointProcessor` saves on
every call; `ModalTrainingGPU` requests one GPU via the `train_gpu` config
string. Multi-GPU means adding a rank/world-size axis that flows from the
runtimes into the pipeline, Engine, strategies, and tracker, with rank-0
gating on every side effect.

**Files touched:** `src/config/runtime.py`, `src/runtime/factory.py`,
`src/apps/train.py`, `src/training/distributed.py` (new),
`src/training/pipeline/_common.py`, `src/training/pipeline/train.py`,
`src/training/pipeline/spawn.py` (new), `src/training/engine.py`,
`src/training/strategies/base.py`, `src/training/strategies/ddp.py` (new),
`src/training/tracking/metric_tracker.py`,
`src/runtime/local.py`, `src/runtime/modal_runtime.py`, `docs/training.md`,
`docs/apps.md`, `tests/test_distributed.py` (new), `tests/test_shard_indices.py`
(new), `tests/test_gpu_resolution.py` (new).

**Depends on documents:** `plans/releases/2.5.md` (the spec),
`plans/releases/2.0.md` §9–§11 and P6/P7 (pipeline/run-lifecycle contracts this
builds on), `plans/archive/1.0.md` F-7 (sampler reseeding semantics),
`docs/training.md`, `docs/apps.md`.

## Decisions made here (closes the open questions in 2.5 §7)

The implementing agent follows these; it does not re-litigate them.

- **Q1 (launcher):** `torch.multiprocessing.spawn` for local runs. In-process,
  testable, no torchrun dependency.
- **Q2 (eval):** eval stays single-process in 2.5. `EvalJob` is untouched and
  `run_eval_pipeline` ignores `n_gpus`. Eval sharding is a v3.0 candidate.
- **Q3 (aggregation):** `all_gather_object` at epoch boundary. Store sizes are
  small (CPU tensors of scalars); streaming reductions buy nothing yet.
- **Q4 (modal gpu key):** keep the single `train_gpu` string, allowing
  `"A10G:4"`. Count is parsed from the string; `--gpus` overrides the count
  while keeping the configured GPU type. No second config key.

One deliberate deviation from 2.5 S2: instead of a `DDPStrategy` mixin that
experiments would have to opt into (breaking S7's "no experiment changes"),
`BaseStrategy.setup_distributed` always performs the DDP wrap when
`world_size > 1`, delegating the torch-specific wrapping to helpers in
`src/training/strategies/ddp.py`. Same code location for the torch details,
no opt-in anywhere.

## Goals

- `citef train --gpus N` trains on N local GPUs (or one Modal container with
  N GPUs) with no change to experiment files or eval jobs.
- `n_gpus == 1` (the default) produces exactly today's behaviour: no
  `torch.distributed` import, no sampler changes, identical checkpoints.
- One MLflow metric series and one checkpoint copy per run, written by rank 0.
- A multi-GPU checkpoint resumes single-process and vice versa.

## Success criteria

- `pytest tests/ -q` green after every branch.
- `pyright <changed files>` clean (strict, per repo config).
- Single-process parity: `citef train -s smoke --no-gpu --subsample 512`
  behaves as before (existing headless-engine tests are the regression net).
- Two-process CPU smoke converges like the single-process smoke:
  `citef train -s smoke --no-gpu --subsample 512 --gpus 2`.
- Exactly one `train_loss-batch` series and one `.pt` artifact per MLflow run
  under `--gpus 2`.
- `grep -n "import torch.distributed" -r src/` matches only
  `src/training/distributed.py` and `src/training/strategies/ddp.py`.

## Tests

Existing suite is the regression net: `pytest tests/ -q`. New suites per
branch are listed in the branch sections. Distributed tests use the `gloo`
backend on CPU so they run on any machine; they live in
`tests/test_distributed.py` and spin real 2-process groups with
`torch.multiprocessing.spawn` and a temp-file init method.

## Abstractions introduced, and what each absorbs

- **`src/training/distributed.py`**, a module-level process-group facade
  (`initialise`, `teardown`, `enabled`, `rank`, `world_size`, `is_primary`,
  `barrier`, `gather_objects`). Every rank check in the codebase calls these
  instead of touching `torch.distributed` directly. Absorbs: swapping NCCL
  defaults, moving to `torchrun` env-var init, adding an FSDP path, or making
  rank injectable for tests, all in one file.
- **`setup_distributed` / `teardown_distributed` hooks on the Strategy
  protocol** with working DDP behaviour on `BaseStrategy`. Absorbs: replacing
  DDP with FSDP later by changing one wrap helper; strategies that need
  custom wrapping override one hook.
- **`shard_indices(indices, *, rank, world_size) -> list[int]`** plus the
  Engine's per-epoch rebuild. Absorbs: a different sharding scheme (window
  partitioning for eval, weighted shards) in one function.
- **`resolve_n_gpus(env, runtime_name, cli_value) -> int`** in
  `src/runtime/factory.py`, the single owner of the "flag beats config beats
  1" rule. Absorbs: new runtime backends adding their own default-GPU logic
  in one place.
- **`spawn_train(job, *, n_gpus) -> RunResult`** in
  `src/training/pipeline/spawn.py`, used by both `LocalRuntime` and the Modal
  container. Absorbs: a new venue (slurm, k8s) reimplementing only the
  process fan-out, not the rank plumbing.

### Step A1. Rank and world size on RunContext; n_gpus on TrainJob

`RunContext` describes how a run executes, so the distributed axis lives
there.

1. In `src/config/runtime.py`, add two fields to `RunContext`:

   callers use `dataclasses.replace`.
2. In `src/training/pipeline/_common.py`, extend `build_run_context` with
   `*, world_size: int = 1, rank: int = 0, gpu_index: int = 0` and pass them
   through; the device becomes

   rank r lands on GPU r. Existing callers compile unchanged thanks to the
   keyword defaults. Update the assert message unchanged otherwise.
3. In `src/training/pipeline/train.py`, add `n_gpus: int = 1` to `TrainJob`.
   Nothing in the pipeline reads it yet (branch E/F consume it); it rides the
   job so the runtimes can see it.
4. Do not touch `EvalJob`, the CLIs, or the runtimes.

Out of scope: `--gpus` flag (E2), Modal parsing (F1), any behavioural change
when the defaults hold.

Verify: `pytest tests/test_pipeline_jobs.py tests/test_headless_engine.py -q`
green; `pyright src/config/runtime.py src/training/pipeline/_common.py` clean.

### Step A2. The distributed facade module

Create `src/training/distributed.py`. This is the only module in `src/`
allowed to import `torch.distributed`, and it does so lazily inside functions
so single-process runs never pay the import.

```python
# Signatures (module-level functions, process-global state)
def initialise(*, rank: int, world_size: int, device: torch.device) -> None
    # no-op when world_size == 1; else init_process_group with
    # backend="nccl" if device.type == "cuda" else "gloo", and
    # init_method=f"file://{tmpfile}" supplied by the caller's env or a
    # tempfile.mkstemp under tempfile.gettempdir(); sets torch.cuda.set_device
    # when on CUDA.
def teardown() -> None            # destroy_process_group when initialised
def enabled() -> bool             # True iff a group was initialised here
def rank() -> int                 # 0 when not enabled
def world_size() -> int           # 1 when not enabled
def is_primary() -> bool          # rank() == 0
def barrier() -> None             # no-op when not enabled
def gather_objects(obj: T) -> list[T] | None
    # all_gather_object across ranks; returns the merged list on every rank;
    # returns [obj] when not enabled.
```

State is a module-private `_State` holding the initialised flag, rank, and
world size; `initialise` raises `RuntimeError` on double-initialisation.
Keep `torch.distributed` imports inside the function bodies.

**Import boundary.** Only modules under `src/training/` may import
`training.distributed`. Everything outside `src/training/` receives
`rank`/`world_size` as plain arguments threaded via `RunContext` (that is
already this plan's design), so the facade can stay private to training
without a second refactor later. Enforcement is structural: a new AST-walk
test `tests/test_import_boundaries.py` fails on any `import`
`training.distributed` / `from training.distributed import ...` statement in
a module outside `src/training/`, following the same idiom as
`tests/test_cli_import_weight.py`.

Out of scope: tensor-specific collectives (branch D adds what it needs on top
of `gather_objects` or a sibling `gather_tensors` in this same file), any
callers.

Verify: `pytest tests/test_distributed.py -q` green, where the test spawns a
2-process gloo group over a temp file and asserts `rank()`/`world_size()`/
`is_primary()` per process plus a round-trip `gather_objects`; a
single-process test asserts `enabled() is False`, `rank() == 0`,
`world_size() == 1`. `pyright src/training/distributed.py` clean.

## Branch C — `feat/engine-sharded-loop`

### Step C1. Per-rank loader sharding in the Engine

In `src/training/engine.py`:

1. Add a module-level helper (or put it in `training/distributed.py`, your
   call, but nowhere else):
   ```python
   def shard_indices(indices: Sequence[int], *, rank: int, world_size: int) -> list[int]
       # indices[rank::world_size]; pure, unit-tested without distributed.
   ```
2. In `train_epoch`, when `distributed.enabled()`: seed reproducibility with
   `torch.manual_seed(_BASE_SEED + epoch)` (module constant, e.g. 0xC0FFEE)
   *before* materialising indices, then build the rank's index list as
   `shard_indices(list(iter(experiment.train_loader.sampler)), rank=..., world_size=...)`
   and iterate a fresh
   `DataLoader(Subset(dataset, shard), batch_size=loader.batch_size, collate_fn=loader.collate_fn)`.
   All ranks run the same seeded sampler iteration, so shards are disjoint
   and their union is the full epoch. When not enabled, the loop is byte
   for byte today's loop.
3. Progress totals: `_total_examples` for the reset should use
   `len(shard)` when distributed. The bars themselves only render where
   `progress is not None`, which branch E wires to rank 0 only; no extra
   gating needed here.
4. Pure-function tests in `tests/test_shard_indices.py`: strided split,
   non-divisible remainder, empty result for rank >= len(indices), union of
   shards equals input for several (n, world_size) pairs.

Out of scope: val-loader sharding (eval is single-process, see Decisions),
`DistributedSampler` (our samplers resample with replacement, so index-list
sharding is the honest mechanism), touching `eval_epoch`.

### Step C2. Pipeline lifecycle and rank-0 side effects

In `src/training/pipeline/train.py` (`run_train_pipeline`):

1. After `build_run_context` (passing `world_size`/`rank`/`gpu_index` from
   the caller-supplied values, which arrive in branch E/F; until then they
   default to 1/0/0), call `distributed.initialise(rank=..., world_size=...,
   device=runtime.device)` and register teardown so the group dies when the
   pipeline returns (try/finally around the whole body).
2. Gate on `distributed.is_primary()`: `set_run_name`, the
   `save_experiment_file` call, `mlflow.log_artifact` for the model source,
   `mlflow.log_params`. Non-primary ranks skip these lines entirely.
3. In `Engine.fit` (same branch, this is the only Engine edit outside C1):
   wrap the checkpoint block in `if distributed.is_primary():` and save
   `model=unwrap(self.experiment.model).state_dict()` so DDP checkpoints are
   identical in shape to single-process ones. Import `unwrap` from
   `training.strategies.ddp`.
4. Call `strategy.setup_distributed(...)` right after the resume-load block
   and `strategy.teardown_distributed()` in the same finally as group
   teardown. Order per epoch: load checkpoint (all ranks read the same
   artifact) then wrap, so DDP broadcasts initial parameters consistently.
5. Resume path needs no changes beyond what exists: every rank loads the
   same MLflow artifact independently.

Out of scope: `mlflow.log_metrics` gating (that call lives in `Engine.fit`
next to `tracker.report`; gate it here too with `is_primary()`), tracker
internals (branch D), spawn mechanics (branch E).

Verify: `pytest tests/test_headless_engine.py tests/test_shard_indices.py
tests/test_pipeline_jobs.py -q` green. Single-process parity:
`citef train -s smoke --no-gpu --subsample 512` still completes and writes
one checkpoint per interval. `pyright src/training/engine.py
src/training/pipeline/train.py` clean.
