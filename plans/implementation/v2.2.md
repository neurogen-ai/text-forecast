# Plan 2.2 implementation — CLI launch speed

Implements [`plans/releases/2.2.md`](../../releases/2.2.md). Read the release
spec first: §2 principles, §3 changes, §5 risks are normative here and are
referenced, not restated.

**Depends on documents:** `plans/releases/2.2.md` (the spec).

## Context

Before this feature, `import main` takes ~7.4s because every CLI invocation
eagerly loads torch, transformers, mlflow, seaborn, sklearn through four
import chains (spec §1.1): the app modules' top-level job/pipeline imports,
`config.loader → config.experiment` (torch), `runtime/__init__` eagerly
importing `runtime.local`, and `data/preprocess/__init__` eagerly
re-exporting `embed_huggingface`/`tokenise`. This plan severs those chains at
their shallowest point without moving any deliberate import-time side effect
(spec §2).

Files touched:

- `src/config/experiment.py`, `src/config/runtime.py`, `src/config/loader.py`
- `src/apps/describe.py`, `engineer.py`, `eval.py`, `train.py`,
  `preprocess.py`, `preprocess_ops.py`, `source_args.py`
- `src/runtime/__init__.py`, `src/runtime/local.py`, `src/runtime/modal_runtime.py`
- `src/data/preprocess/embed_registry.py` (new), `src/data/preprocess/__init__.py`,
  `src/data/preprocess/embed_huggingface.py`, `src/data/preprocess/pipeline.py`
- `tests/test_cli_import_weight.py` (new)

## Goals

1. Cold `import main` loads none of torch / transformers / mlflow / seaborn /
   sklearn (verified by subprocess `sys.modules` assertions).
2. Every modal client path (build_runtime("modal"), job construction, spawn)
   completes without importing torch or transformers.
3. The two deliberate module-level side effects (`apps/train.py`
   `warnings.filterwarnings`; `apps/preprocess.py` `TOKENIZERS_PARALLELISM`)
   still fire at app-module import time.
4. Full pytest suite passes unchanged except the added test file.

## Success criteria

- `PYTHONPATH=src python -c "import main"` wall-time < 3s (expect < 1s).
- New structural test green; existing suite green.
- pyright passes (stringified annotations must resolve via `TYPE_CHECKING`).

## Logical git commits

One commit per branch, message given at the end of each branch below.
Branches land in dependency order; within a branch, steps are commit-sized
chunks but squash to the branch commit unless a step says otherwise.

## Decision tree

```
A config chain ──────────────┐
B embedder registry split ───┼──► E test + measurement + docs
C app modules lazy ──────────┘         (needs all of A–D)
D runtimes lazy ── (needs B)
```

- **A, B, C are mutually independent** — any order, or in parallel by three
  agents/worktrees.
- **D depends on B**: `ModalRuntime`'s client-side helpers read embedder
  metadata from the new light registry created in B.
- **E depends on A+B+C+D**: the structural test asserts the *combined* end
  state; running it earlier produces false failures.

Spec: §3.1. Files: `config/experiment.py`, `config/runtime.py`,

### Step A1 — TYPE_CHECKING the torch-typed config classes

In `src/config/experiment.py`:

- Remove module-level `from torch import nn`,
  `from torch.utils.data import DataLoader`, `from training.checkpointing
  import CheckpointProcessor`, `from training.strategies import Strategy`,
  `from training.tracking.base import MetricTracker`.
- Add:
  ```python
  from typing import TYPE_CHECKING
  if TYPE_CHECKING:
      from torch import nn
      from torch.utils.data import DataLoader
      from training.checkpointing import CheckpointProcessor
      from training.strategies import Strategy
      from training.tracking.base import MetricTracker
  ```
  The file already has `from __future__ import annotations`, so field
  annotations resolve for type-checkers as strings at runtime.
- Directly above `class Experiment`, add this exact comment:
  `# Invariant (plan 2.2 §3.1): nothing may call typing.get_type_hints on
  Experiment at runtime; annotations are stringified.`

Apply the identical transformation in `src/config/runtime.py` for `import
torch` → `TYPE_CHECKING` block containing `import torch`, and add the same
invariant comment above `class RunContext`.

Additional constraint for Branch A: `src/data/preprocess/steps.py`
calls `typing.get_type_hints` at runtime (`_coerce`, ~line 97) on the step
dataclasses composing the `PipelineStep` Union (`CleanStep`,
`TokeniseStep`, `EmbedStep`, `DropNaStep`; `steps.py:67`), so while
migrating any module behind
`TYPE_CHECKING`, every name referenced in those dataclass annotations must
remain eagerly imported (move only names that appear exclusively inside
function bodies or non-annotated positions). `StepContext` is exempt —
its annotations are never resolved via `get_type_hints` — but its
`logging.Logger` annotation depends on `import logging`, which step 0
made eager; keep it eager.

Add a parametrized guard to `tests/test_steps.py`:

```python
# Invariant (plan 2.2 §3.1): the step dataclasses in PipelineStep are
# resolved via get_type_hints at runtime by _coerce; a TYPE_CHECKING-only
# import referenced in their annotations would raise NameError here.
# PipelineStep is a Union alias (see _STEP_TYPES), so iterate __args__.
@pytest.mark.parametrize("cls", PipelineStep.__args__)
def test_step_annotations_resolve_at_runtime(cls):
    hints = typing.get_type_hints(cls)  # raises NameError on failure
    assert {f.name for f in dataclasses.fields(cls)} <= set(hints)
```

When extending `PipelineStep` in later branches, run this test before
committing; any new annotation name must be eagerly imported or must not
live behind `TYPE_CHECKING`.

Out of scope: touching any caller of these classes; touching
`config/env.py`; changing any annotation text.

Verify: `PYTHONPATH=src python -c "import config.loader"` succeeds AND
`PYTHONPATH=src python -c "import sys, config.loader; assert 'torch' not in sys.modules; print('ok')"`
prints `ok`. Then
`pytest tests/test_pipeline_jobs.py tests/test_steps.py -q` passes.

# Branch B — embedder registry split

`runtime/modal_runtime.py` needs that metadata on the client (its
`_embedder_config` / `_resolve_output_dim`). Splitting the registry out is
the abstraction that lets new embedder models be added in exactly one file
forever.

# Branch E — structural test, measurement, docs

Depends on A+B+C+D all landed.

### Step E1 — `tests/test_cli_import_weight.py`

Three tests, each spawning a fresh interpreter (subprocess, env with
`PYTHONPATH=src`) so `sys.modules` state cannot leak between cases:

```python
def _modules_of(code: str) -> set[str]:
    probe = (
        "import sys; "
        f"exec({code!r}); "
        "print(sorted(m.split('.')[0] for m in sys.modules))"
    )
    out = subprocess.run(
        [sys.executable, "-c", probe], capture_output=True, text=True, check=True
    )
    return set(ast.literal_eval(out.stdout))
```

1. `test_import_main_is_light`: modules of `import main`; assert
   `{"torch", "transformers", "mlflow", "seaborn", "sklearn"}` disjoint from
   it; assert elapsed wall-time < 3.0s (generous ceiling, spec §3.5).
2. `test_modal_client_paths_are_torch_free`: modules of
   `import runtime.modal_runtime`; same disjoint assertion plus
   `"training"`, `"models"`.
3. `test_deliberate_side_effects_survive`: modules of
   `import apps.train, apps.preprocess`; then in-process-style probe code
   asserts `warnings.filters != []` shows the ignore filter is present and
   `os.environ["TOKENIZERS_PARALLELISM"] == "true"`. Implement as two small
   probes printing sentinels rather than parsing filters: append to the exec
   string `print(os.environ.get("TOKENIZERS_PARALLELISM"))` and for train
   `import warnings; print(any(f[0] is warnings.filterwarnings and False for f in warnings.filters) or len(warnings.filters))`
   — concretely: capture `len(warnings.filters)` before/after is impossible
   cross-process, so instead assert `len(warnings.filters) > 0` and that
   `apps.train` is in modules. Keep it simple; the meaningful regression
   guard is someone deleting the line, which `len(warnings.filters) > 0`
   catches on this repo (no other filter sources at import time).

4. `test_no_import_time_config_reads_outside_runtime`: the one test in this
   module that needs no subprocess. AST-parse every `src/**/*.py` file and
   assert no module-level (function-def-free, i.e. directly in the module
   body) call to `load_env(...)` or `modal_runtime_config(...)` appears in a
   module outside `src/runtime/`. Static AST rather than a behavioural probe
   because `load_env()` has no injectable config path — there is no way to
   observe the read without executing it, and importing real modules is what
   this guard exists to prevent ordering hazards around. Deliberate import-
   time config use stays legal inside `src/runtime/` (see plan 2.5's Tests
   section for that invariant going forward).

Mark the module with `@pytest.mark.skipif(sys.platform == "win32", ...)`
only if needed — default assume POSIX.

Out of scope: asserting specific timings tighter than 3s; testing
subcommand execution (dispatch is covered by existing suites).

Verify: `pytest tests/test_cli_import_weight.py -v` — 4 passed.
