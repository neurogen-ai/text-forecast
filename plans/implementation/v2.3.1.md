# v2.3.1 implementation: MLflow logging and param-tracking fixes

Implements [`plans/releases/v2.3.1.md`](../releases/v2.3.1.md). The scope
checklist and technical approach there are binding; decisions live in
[`plans/proposals/v2.3.1-mlflow-logging-fix.md`](../proposals/v2.3.1-mlflow-logging-fix.md)
(AD1 through AD10) and [`design/tracking-stores.md`](../../design/tracking-stores.md).
This plan references them and does not restate the reasoning.

## Context

Training and eval runs report to MLflow through `MetricTracker`
(src/training/tracking/metric_tracker.py) and five task-tracker subclasses
that share the same store names. Two defects and two gaps came out of the
2026-09-06 run: `ClassificationStrategy.training_step` never feeds
`train_ids` while every tracker gathers `{prefix}_ids` for both prefixes, so
`_gather_store` logs an empty-store ERROR nine times a day; `run_eval_pipeline`
starts its MLflow run before setting the tracking URI; the tracking package
swallows exceptions with bare `logger.error(e)`; and train runs log four
params, so tuned values (optimizer spec, scheduler spec, epochs, batch sizes,
model configs) are recorded nowhere. Two dead helpers, `log_params.py` and
`_get_scheduler_params.py`, make param logging look handled when it is not.

Areas touched: `src/training/tracking/` (five tracker modules, two new param
modules, two deletions), `src/training/strategies/classification.py`,
`src/training/pipeline/train.py` and `eval.py`, plus tests under `tests/`.

All branches cut from the `2.3.1` integration branch, which carries the
ratified release and proposal docs (main does not yet).

## Goals

1. The train path feeds `train_ids`, with NaN-fallback id batches skipping the
   feed on both paths (design/tracking-stores.md, rule 2).
2. The empty-store message in `_gather_store` latches to one WARNING per store
   name per tracker instance instead of an ERROR per epoch.
3. `run_eval_pipeline` resolves its run against `job.env.tracking_uri`.
4. Tracking-package exception handlers log traceback plus context.
5. Every train run logs the full resolved hyperparameter set at start, with
   bare leaf keys and table-driven suffix disambiguation.
6. Dead `log_params` and `_get_scheduler_params` helpers are deleted.

## Success criteria

- `pytest` and `pyright` pass; existing tests unchanged except additions.
- No metric names or values change. `train_ids` joins the export payload when
  export is enabled; record that in the feed commit (release doc, friction).
- Descope triggers from the release doc, each with a home:

  | Trigger | Home |
  |---|---|
  | NaN-mix: a train config mixes real and fallback ids in one batch, so the feed lines are cut and the latch plus URI reorder ship alone | Id survey recorded in the body of the `v2.3.1-id-feed` commit (below) |
  | Plot-spam: plot-path `logger.exception` spams tracebacks per eval epoch, so the plot swaps are cut and `calc_metrics` keeps the fix | Contingency commit `revert(tracking): restore logger.error in the plot paths` on `v2.3.1-log-exception`; check the first eval run's log |
  | Walker-raise: the walker raises on any existing experiment config at run start, so it is cut for an explicit hand-written param dict | Contingency commit `feat(pipeline): replace param walker with an explicit param dict` on `v2.3.1-train-params`; checked by the param smoke below |
  | Model-config: flattening a model's `self.config` fails to serialize, so that family rides `model_class` only | Same smoke; fix is a one-line root exclusion in `compose_train_params` |

- Acceptance: param smoke. After `v2.3.1-train-params`, run one short train
  (single epoch) of each existing experiment config (`graph_embed_class`,
  `retrieval_forecast`, `transformer_class`) and confirm the run's param table
  populates with no walker raise and no MLflow immutability error.
- Acceptance: id survey. The `v2.3.1-id-feed` commit body records, per
  experiment config, that train id tensors are fully real or fully NaN per
  batch, never mixed. Mixed ids fire the NaN-mix trigger.
- Acceptance: first eval run log after `v2.3.1-log-exception` shows no
  per-epoch plot tracebacks. Spam fires the plot-spam trigger.
- No version bump in `pyproject.toml`; version bumps happen at release time.

## Branch naming

All branches start with the release semver. Ordinary branches match
`^v\d+\.\d+\.\d+-(?!PR-)[a-z0-9-]+$`; PR branches match
`^v\d+\.\d+\.\d+-PR-[a-z0-9-]+$`. The `PR-` prefix belongs to PR branches
only. A renamed branch is deleted and rebranched.

## Decision tree

```
v2.3.1-param-walker ──► v2.3.1-train-params ──► v2.3.1-PR-train-params

v2.3.1-id-feed ─────────┐
v2.3.1-store-latch ─────┤
v2.3.1-log-exception ───┼──► v2.3.1-PR-tracking-logs
v2.3.1-eval-uri ────────┘
```

Every arrow is a merge, dependency into dependent. The two PR branches are
independent of each other: their file sets are disjoint (PR 1 touches
`classification.py`, the tracker modules, and `eval.py`; PR 2 touches
`params.py`, `param_keys.py`, `train.py`, and the two deleted helper files).
Each PR branch opens as a PR against main; the merge to main is release-time
work and out of scope here.

The one seam is `src/training/tracking/params.py`: `v2.3.1-train-params`
waits on it, and the contract is the first skeleton under Foundational
contracts. The four PR-1 branches wait on nothing and can run in parallel
worktrees. `store-latch` and `log-exception` both edit `metric_tracker.py`
but in disjoint hunks (`_gather_store` vs the `logger.error(e)` sites), so
they merge cleanly in either order.

## Branches

### v2.3.1-param-walker

The foundation: generic scalar collection and the key scheme, with no
callers yet. Touches `src/training/tracking/params.py` (new),
`src/training/tracking/param_keys.py` (new), `tests/test_param_walker.py`
(new), `tests/test_param_keys.py` (new).

Commits, in order:

1. `feat(tracking): add scalar param walker with guarded MLflow logging`.
   Adds `Leaf`, `collect_scalars`, `log_params_guarded`, with unit tests over
   synthetic dataclasses, pydantic models, live-object fields, and None.
   Tested against a mocked MLflow client; no server.
2. `feat(tracking): add param key scheme driven by an explicit rename table`.
   Adds `SUFFIX_RULES`, `resolve_keys`, with tests for bare keys, bare-plus-suffix
   duplication, and the differing-value collision raise.

Contracts are the review anchor; see Foundational contracts. Both commits
leave the tree green: new modules plus their tests, nothing imports them.

### v2.3.1-train-params

Wires the walker into the train pipeline and removes the dead code. Depends
on `v2.3.1-param-walker` (the params.py seam). Touches
`src/training/pipeline/train.py`, `src/training/tracking/__init__.py`,
deletes `src/training/tracking/log_params.py` and
`src/training/tracking/_get_scheduler_params.py`, adds
`tests/test_train_params.py`.

Commits, in order:

1. `refactor(tracking): delete dead log_params helpers`. Removes both files
   and the `log_params` re-export and `__all__` entry in
   `tracking/__init__.py`. The commit body records the grep: no callers.
   Deleting first clears the name for the new scheme.
2. `feat(pipeline): log full hyperparameters at train start`. Adds a
   `compose_train_params(exp)` function in `train.py` that assembles the
   walker roots, called inside the existing `start_run` block through
   `log_params_guarded`, replacing the four-key `mlflow.log_params` dict.
   Composition, decided here:
   - `("experiment", {"experiment_name": ..., "model_class":
     type(exp.model).__name__})` as an explicit mapping (the four legacy keys
     fold in per AD7 as `experiment_name`, `model_class`, `examples-train`,
     `examples-val`).
   - `("train", {"examples": len(exp.train_loader.dataset), "batch_size":
     exp.train_loader.batch_size})`, and the same under `("val", ...)` as
     explicit mappings.
   - `("runtime", runtime)` and `("strategy", exp.strategy.config)` as
     instance roots; the specs inside StrategyConfig recurse, and its live
     objects (model, tracker, stream, device) stringify as class names, which
     the scalar filter must survive without raising (release doc friction).
   - `("model", cfg)` where `cfg = getattr(exp.model, "config", None)`,
     included only when `cfg` is a dataclass or pydantic instance. A class
     attribute (graph_recurrent's `config = ModelConfig`) is not an instance,
     so graph_recurrent rides `model_class` only, per AD8, with no special
     case.
   Tests stub the experiment (the function reads only the attributes listed
   above) and assert the emitted key set, including the ambiguous-leaf
   duplication. If the walker-raise or model-config trigger fires, the
   contingency moves named under Success criteria land on this branch.

## Foundational contracts

Two abstractions, both in PR 2, both built to absorb change in one place.

### `src/training/tracking/params.py`

The walker owns "what counts as a param". A new param source is one root in
`compose_train_params`; a new field on any config dataclass or pydantic model
is picked up with no code change; a new exotic field type is one branch in the
scalar filter. Nothing outside this module knows how collection works.

```python
LeafValue = bool | int | float | str

class Leaf(NamedTuple):
    value: LeafValue
    origin: str  # component path, e.g. "model.config.embedder" or "train"

def collect_scalars(*roots: tuple[str, object]) -> dict[str, Leaf]:
    """Recurse dataclass and pydantic BaseModel instances field by field;
    treat Mapping[str, scalar] roots as explicit leaves. Keep
    str/int/float/bool leaves; stringify other objects as their class name,
    with None as "None". Raise KeyError naming the colliding paths when two
    bare leaves carry different values."""

def log_params_guarded(params: dict[str, str]) -> None:
    """Log params to the active MLflow run, truncating values to the MLflow
    cap instead of raising. Identical values are a no-op; changed values log
    a warning and keep the original (params are immutable per run)."""
```

The guarded log exists because the train pipeline reuses `job.run_id` on
resume (AD9). A future change to resume policy, warn or raise, lands in this
one function.

### `src/training/tracking/param_keys.py`

The rename table owns every non-bare key (AD10). A new ambiguous leaf or a
key rename is one table row; no caller edits, and every suffixed key is
visible in one list.

```python
SUFFIX_RULES: dict[str, tuple[str, ...]] = {
    "embed_dim": ("embedder", "forecaster"),
    "batch_size": ("train", "val"),
    "examples": ("train", "val"),
}

def resolve_keys(leaves: dict[str, Leaf]) -> dict[str, str]:
    """Every leaf emits its bare key. A leaf named in SUFFIX_RULES also
    emits "<leaf>-<suffix>" for each suffix that appears as a segment of its
    origin, so the key set is a pure function of the leaves and the table
    and is identical across runs. For a tabled leaf with differing values,
    the bare key carries the value of the first origin in walker
    declaration order; each origin's value also carries its suffixed key.
    Unknown bare-key collisions surface as the walker's KeyError."""
```

Anything these two modules raise on a real config is the walker-raise or
model-config trigger path, not a bug to patch around: the fallback is the
named contingency commit, and the owner call is already recorded in the
proposal.
