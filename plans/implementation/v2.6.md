Implements `plans/releases/2.6.md`. Refined against the code as of commit
`89d6cd2` (post-2.1 preprocess rebuild, pre-2.5 runtime tidy). Each branch is

## Context

The 2.0 release added hybrid local/Modal execution: `ModalRuntime` dispatches
preprocess/train/eval to Modal containers built inline in
`src/runtime/modal_runtime.py`, fire-and-forget via `RunResult.modal_function_call_id`.
Nothing watches those spawned jobs, images are rebuilt from source on every
import, config credentials would live in `config.toml` if any existed, datasets
are unversioned volumes, and there is no CI.

**Files touched:** `src/runtime/modal_images.py` (new),
`src/runtime/modal_secrets.py` (new), `src/runtime/monitoring.py` (new),
`src/runtime/modal_scheduled.py` (new), `src/runtime/modal_runtime.py`,
`src/config/env.py`, `src/apps/status.py` (new), `src/main.py`,
`src/apps/preprocess.py`, `src/apps/source_args.py`,
`src/data/sources/modal.py`, `src/data/preprocess/pipeline.py`,
`.github/workflows/smoke-tests.yml`, `.github/workflows/modal-image.yml`,
`scripts/deploy_modal.py` (new), `config/config.example.toml`, `docs/*`.

**Depends on documents:** `plans/releases/2.6.md` (the spec),

no remote progress reporter here),

## Deviations from plans/releases/2.6.md found during inspection

Already reflected in the branch files; the implementing agent does not need to
reconcile them.

1. The spec's `infra/modal/images.py` would put the image builder outside the
   `PYTHONPATH=src` layout that every other module uses. Images instead live in
   `src/runtime/modal_images.py`; only the CI deploy script lives under
   `scripts/`.
2. The spec's `MonitoredModalJob` class wrapper is replaced by three free
   functions in `monitoring.py` plus a `citef status` command. A wrapper class
   around `run_*` would duplicate the four dispatch methods' signatures for one
   call site each; functions compose at the CLI layer instead.
3. Heartbeat-to-MLflow hang detection (spec §6.2) is deferred to plan 2.8
   (its F-35 feeds reporter heartbeats into health checks). Branch E ships
   poll-based status with timeout surfaced as an error; no MLflow heartbeat
   writer is added here.
4. The spec's `ModalVolumeSource` dataclass duplicates the existing
   `ModalDataSource`. Versioning extends `ModalDataSource` with an optional
   `version` field; no new class.
5. Image "publish on PR" is not possible: Modal builds images at deploy time
   and ad-hoc images are not named registry artefacts. Branch D deploys the app
   on tags (which builds and pins the image for those functions) and bakes the
   git tag into the image as `TEXT_FORECAST_VERSION`.

## Goals

- CI runs typecheck and tests on every PR with no Modal credentials.
- One owner of Modal image construction; `[runtime.modal].image_tag` can pin a
  deployed image instead of rebuilding from source.
- No secret values ever pass through `config.toml`; config carries secret
  *names* only.
- A spawned train/eval job can be followed locally by id and its dispatch
  retried on transient failure.
- Datasets carry optional versions; preprocessing can run incrementally over
  new raw partitions only.
- Scheduled retrain and web endpoints exist but deploy nothing until opted in.

## Success criteria

- `pytest tests/ -q` green after every branch; `basedpyright` clean on changed
  modules.
- `.github/workflows/smoke-tests.yml` passes on this repo without any secrets
  configured.
- `grep -rn "from_name" src/runtime/ | grep -i secret` shows secret names come
  only from `modal_secrets.py`; no secret *values* appear anywhere under
  `config/`.
- `grep -n "modal.Image" src/runtime/modal_runtime.py` matches nothing (images
  imported from `modal_images.py`).
- `.venv/bin/text-forecast status --help` works offline (no modal import
  needed for `--help`).
- `ModalDataSource(volume="v", name="n", version="2024-01").resolve()` returns
  `/modal/v/n/2024-01`.

## Tests

Existing suite is the regression net. New test files per branch are listed in
each branch section. Modules touching `modal` keep it out of module-level
imports where practical so tests run without the package's network side
effects (follow the `runtime/modal_env.py` split pattern).

Import-time invariant going forward: module-level config reads
(`load_env(...)`, `modal_runtime_config(...)`) and env-var reads stay confined
to `src/runtime/`, enforced by the static AST test specified in plan 2.2
branch E (`test_no_import_time_config_reads_outside_runtime` in
`tests/test_cli_import_weight.py`). The exemption is wholesale for
`src/runtime/`, including env-var reads: branch D makes `modal_runtime.py`
read `os.environ["TEXT_FORECAST_VERSION"]` at import, so carving out config
calls but not env vars would be unenforceable. Consequently
`runtime/modal_scheduled.py` sits inside the exemption zone too — new modules
outside `src/runtime/` must take config through arguments, not imports.

## Abstractions introduced, and what each absorbs

- **`build_preprocess_image(cfg)` in `runtime/modal_images.py`.** Absorbs new
  image layers (extra apt packages, model caches, baked version env): change
  lands in one function; both the training container and any future scheduled/
  endpoint container pick it up.
- **`[runtime.modal].secrets: list[str]` + `secret_objects()` in
  `runtime/modal_secrets.py`.** Absorbs adding credentials (a new API key): add
  the name in config, create it once with `modal secret create`. No code
  change.
- **Free-function monitoring API (`status_from_call`, `spawn_with_retry`,
  `wait_for_call`) taking duck-typed call objects.** Absorbs a transport swap
  (plan 2.8 reporter endpoints, different polling backend): the functions never
  import modal at module level, so a new backend means passing a different call
  object.
- **`version: str | None` on `ModalDataSource`.** Absorbs dataset rollbacks and
  "latest" pointers: callers already thread source config generically through
  `--source-opt` / `SourceBackend.__init__`, so no call-site changes.
- **`inputs` map in staged `metadata.json` + `select_incremental_inputs()`.**
  Absorbs changed freshness rules (mtime, checksums, row counts): the diff rule
  lives in one pure function.
- **Config-gated deployment split (`runtime/modal_scheduled.py` deployed
  separately).** Absorbs more scheduled jobs/endpoints: they join their own
  deployable module without touching the core runtime.

# Branch E — `feat/job-monitoring`

Poll status and retry helpers for spawned jobs, exposed as `citef status`.
Spec §6. Depends on B only for the small `modal_runtime.py` wiring in E2; the
core module (E1) has no deps and may start immediately.

## Step E1 — Monitoring core

**Files:** `src/runtime/monitoring.py` (new), `tests/test_monitoring.py` (new).

**Contracts (no modal import anywhere in this module):**

```python
@dataclass(frozen=True)
class JobStatus:
    state: str                 # "pending" | "running" | "done" | "error"
    done: bool
    returncode: int | None     # 0 on success, non-zero on failure, None while pending

def status_from_call(call: Any) -> JobStatus:
    """Read one poll snapshot from a modal.FunctionCall-like object.

    ``call`` must implement ``poll() -> object | None`` (None while pending)
    and ``returncode`` semantics matching modal: exception objects count as
    error. Duck-typed so tests pass fakes.
    """

def wait_for_call(call: Any, *, poll_interval_s: float, timeout_s: float) -> JobStatus:
    """Poll until done; raise TimeoutError if timeout_s elapses first."""

def spawn_with_retry(spawn: Callable[[], T], *, attempts: int = 3,
                     backoff_s: float = 5.0, sleep: Callable[[float], None] = time.sleep) -> T:
    """Call spawn(); on exception retry up to attempts-1 times with backoff.

    Retries dispatch/transient errors only; the final exception propagates.
    ``sleep`` injectable for tests.
    """
```

- `status_from_call` mapping rules (decide here, don't defer):
  `call.poll() is None` → pending; returned object is an `Exception` instance
  → `error`, done, returncode 1; anything else → `done`, returncode 0.
- `wait_for_call` loops `status_from_call`, sleeping between polls; on
  timeout raises `TimeoutError(f"job did not finish within {timeout_s}s")`.

Tests with fake call objects: pending→done transitions, exception→error,
timeout raising (use `poll_interval_s=0`), retry succeeding on second attempt
with recorded sleeps, retry exhausting and raising the last error.

**Out of scope:** log streaming from containers; MLflow heartbeats (plan 2.8);
cancelling jobs; any modal_runtime changes.

**Verify:** `.venv/bin/python -m pytest tests/test_monitoring.py -q` green.
Commit: `feat(monitoring): poll/retry helpers for spawned modal jobs`.
